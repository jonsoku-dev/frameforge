# Create a film

Motion graphics (showreel, reel, ident, launch, promo, brand film, "show off", "go all out"), including a quiet promo: stop here and follow `../frameforge-motion/SKILL.md` instead of the steps below. The steps below are for explainers, process films, captions, charts and data films.

1. Repository root = two folders above this file (it holds `package.json` with `"name": "frameforge-local"`). If `node_modules` is missing, install dependencies only when authorized; otherwise report the gap.
2. Choose new or revise from the request. For a new film, pick a slug (kebab-case) and copy `examples/samples/_template/` to `examples/samples/<slug>/`; rename `template.audio.json` to `audio.json`, set `"slug"`, and change `./template.audio.json` to `./audio.json` in `Spot.tsx`. For a revision, read the existing brief, plan, entry, relevant source and specified saved output first. Preserve the original request, history and user-owned assets; do not recreate the film. If a new explicit instruction changes an earlier condition, record the supersession and follow the latest instruction.
   For a new film outside the engine repository, run `frameforge init <dir>` once (or `node <engine>/bin/frameforge.mjs init <dir>`), then `frameforge new <slug>` inside it. That copies the template to `films/<slug>/`, applies every rename and registers it in `films/index.tsx`; use `frameforge score|art|lint|render|studio|check` there instead of the npm scripts, with `films/<slug>` in place of `examples/samples/<slug>`.
3. Engine brief first: for a new film fill `brief.md` (copied with the template) before anything else. For a revision, preserve the original request and history while merging the new requirements and decisions into the existing brief. Record when the user explicitly supersedes an earlier condition and follow the latest instruction. `## Request` is the user's request verbatim, unchanged. `## Intent ledger` has one row per clause, split so no word of the request is left over: the clause quoted exactly, its kind (`must`, `forbid`, `taste`, or `implied` for what the genre expects but nobody said, such as a name in a showreel or a product reveal in a launch), the concrete engine means (the rendering technique you will write, an `audio.json` field, a size, fps or duration) and where it is verified (a Structure row and frame range, or a check). `## Engine translation` restates the film in engine vocabulary: concept, world, hero, palette, rendering layers, duration, size, fps, audio. It may add detail but never contradicts, weakens or drops an active must or forbid row; taste rows hold unless they conflict with a must; implied rows never override a stated clause; when the request is open ("you pick") commit to bold choices and label them `Decision:`, not as the user's intent. `## Gaps` lists what the engine cannot do or what conflicts, with the substitute chosen (`None.` when empty); nothing is dropped silently. Run `node bin/frameforge.mjs brief-check <slug>` (or `npm run brief-check -- examples/samples/<slug>`) and report its actual result: it fails on an empty request, a row without means or verification, a request sentence no clause covers (naming it and the missing words), and seconds, WxH or fps in a must clause that differ from `entry.tsx`. A superseded original condition may still be flagged; retain the original request and report the conflict instead of changing it to force a PASS.
4. For a new film, write `prompt.md` following the Engine translation; for a revision, preserve the existing plan and update only what the new request requires. Use the template's sections when applicable: Inputs, Direction (it opens with a `Concept:` paragraph) with a `Banned:` line, Structure in absolute frames, Build (the rendering plan), Second pass, Gotchas. Use a beat grid when it serves the brief. Show the Structure table before writing code. Rules: `docs/samples/rules.md` 기획 구조.
   - Concept first: one paragraph with the single idea, the world it happens in, one hero that recurs and changes state, a palette derived from the concept (never a default), the signature moves this concept needs, and how motion enacts each line of copy (`../frameforge-best-practices/references/kinetic-type.md`). Self-check: if the scene list could be pasted into another prompt's film unchanged, start again. Nothing in this repository's docs or examples is a scene, palette or line to reuse.
5. Build by film kind.
   - **Motion graphics**: use `../frameforge-motion/SKILL.md` instead of this workflow.
   - **Explainer, process, captions, charts, data film, a calm film the request asks for**: the utilities appendix (`../frameforge-best-practices/references/utilities.md`) lists blocks, the motif kit, assets, shader presets, narration and captions you may use; bespoke code is still allowed wherever it serves better.
   - Mark a DOM hero `data-subject="<name>"` when useful. Choose type for the brief and available, authorized fonts; `googleFont` can access the network. Prefer a reproducible licensed local font when external access is unavailable, and report any font substitution or system-font variability. Avoid unnecessary corner readouts; if a scoreboard or another HUD carries requested information, opt in with `data-hud="allow"` and record the reason. Avoid technique or scene names as on-screen labels and unintended blank transition frames; report an intentional conflict with the diagnostic. Invented names stay fictional, plausible and specific, and the Inputs say so; sample numbers carry one small footnote in the film's language.
   - Match the opening, transitions and ending to the request. Use motion to communicate, and retain enough settled time to read. Review frame-check results against the intent and report any conflict without changing the actual result.
6. For a new film, write `Spot.tsx` as a pure function of `useCurrentFrame()`. For a revision, make only the needed changes to existing relevant files instead of replacing `Spot.tsx` by default. Use `beatsFromSpec(spec, fps)` and motion-derived sound when they serve the brief (`../frameforge-best-practices/references/motion.md`, `sound.md`). A spoken film is narration-first (`../frameforge-voice/SKILL.md`). `entry.tsx` registers the composition; for a new film add one import and one `<Composition>` line to `examples/samples/index.tsx` if needed. Do not duplicate an existing registration during a revision.
7. Preserve requested audio or silence. Generate sound with `npm run score -- examples/samples/<slug>/audio.json` only when it fits the request and its sources are authorized. Outside snapshot mode, the renderer generates a score whenever `audio.json` exists: for a newly copied template, remove its unused audio file and import when no score is needed. Never delete user-owned files; if available tools cannot remove the unused template, report that limitation. Verify the final mix when listening is available.
8. Second pass: within the authorized scope, inspect relevant states and the last requested frame. Before rendering a contact sheet or still, check whether asset generation, network requests or other out-of-range effects are permitted; frame selection alone does not prevent them. If this route is not allowed or cannot be assessed, use an authorized observation method or mark the affected observations NOT VERIFIED. Critique their purposes in `prompt.md`, revise the weakest scenes and inspect the revision with an authorized method before final render.
9. Check and render as `frameforge-check` and `frameforge-render` say; `frameforge check <out.mp4> --film <slug>` includes the `brief` row. Canvas and shader text is not in the audit: inspect its size, margin and contrast using an authorized observation method, or report them NOT VERIFIED.
10. Self-review before delivery: re-read the ledger against the frames and check output. Report every must and forbid clause as MET, UNMET or NOT VERIFIED with evidence, actual check statuses, every Gap and its substitute, and what was observed. Watch and listen at playback speed when available; stills and measurements are not playback or listening.
