# Create a film

1. Repository root = two folders above this file (it holds `package.json` with `"name": "frameforge-local"`). Run `npm install` once if `node_modules` is missing.
2. Pick a slug (kebab-case) and copy `examples/samples/_template/` to `examples/samples/<slug>/`; rename `template.audio.json` to `audio.json` and set `"slug"`.
   Not inside the engine repository: run `frameforge init <dir>` once (or `node <engine>/bin/frameforge.mjs init <dir>`), then `frameforge new <slug>` inside it. That copies the template to `films/<slug>/`, renames the id to the PascalCase slug, and registers it in `films/index.tsx`; use `frameforge score|art|lint|render|studio|check` there instead of the npm scripts, with `films/<slug>` in place of `examples/samples/<slug>`.
3. Write `prompt.md` first in the template's six sections: Inputs, Direction with a `Banned:` line, Structure on the beat grid (absolute frames, what the hero becomes and what the camera fills in each row), Build, Gotchas, Start. Show the Structure table before writing code. Rules: `docs/samples/rules.md` 기획 구조; worked example: `examples/samples/morph-ui/prompt.md`.
   - Motion graphics means spectacle and continuity by default: every second shows at least one active effect or transformation, the camera never fully stops, scenes morph into each other (continuous morph is the default grammar for showreels, launches and idents), the frame is layered (foreground type, an effect, a textured background) and the technique changes on every beat. Restraint (a calm explainer) only when the request asks for it. Recipe and components: `../frameforge-best-practices/references/showreel.md`.
   - The hook: frame 0 to 30 of every film is a striking, frame-filling image or action (a macro crop of the hero, a full-bleed texture, the first pour already moving, a headline larger than the frame). Never a small mark, dot or logo on an empty field; frame-check counts that second as empty or huddled.
   - A process request: the composition evolves step by step (the camera reframes, a tracker fills, completed items accumulate, the card moves); never the same layout repeated across steps.
   - A process request: hero props are illustrated objects, not icons (recognisable silhouette, a label or detail, highlight and shadow, one outline weight; kit `Bottle`, `Glass` or drawn in `assets.tsx`), and tools are shown in use: the bottle tilts and pours from its own neck (`<Stream from={bottleNeck({size, tilt, x, y})}>`).
   - A process request (recipe, how it works, assembly, data flowing): every Structure row names a cause and its visible effect in the same frames (the bottle tilts and `<Stream>` pours while the level rises past labelled marks; the arrow carries the item into the box). From the first frame of a pour the level and the count both change in the frames where the stream is visible; a quantity never sits at zero under a visible stream. The subject stays whole in frame; quantities are labelled on the object.
   - A showreel, reel or brand film: name six to eight distinct techniques in Direction, each with the component that makes it: glow on type (`<Glow>`), chromatic split (`<ChromaticShift>`), CRT and VHS (`<Scanlines>`, `<VhsGlitch>`), extruded 3D type (`<Extrude>`), 3D perspective card fly-throughs, an image-like shader field (`<Shader>` presets), a drawn curve or waveform. A film that uses one technique throughout reads as a template.
   - For image-like texture (macro, liquid, tunnel, grain) use `<Shader>` presets, never stock images.
   - "Go crazy", "go all out", "wow" or "make it insane": maximal density. A new technique on every beat (no technique twice in a row), at least one full-frame image-like texture moment (a macro crop, `<Generative system="halftone">` or grain over a photographic-feeling generative field), cuts on the beat, and one cinematic camera move (a push through, an orbit or a fly-through in 3D perspective). Every word stays legible: whole words only, no garbled states, headlines held 1.2 s.
   - Invented names (clients, products, cities, people) are plausible and specific: "Halden Coffee", "Mira Osei", "Northfield Transit", never "Client A", "Brand X" or "Company 1". They stay fictional and the Inputs say so.
   - Sample data is labelled once, small, in the film's language: one footnote on the beat ("Sample data" in English, "サンプルデータ", "샘플 데이터"), not a tag on every stat. Blocks take `example` as `true | false | 'text'` and pick Sample, サンプル or 예시 from `lang` or the script of their own copy; pass `example={false}` on every block but the one that carries the tag, or on all of them when a footnote does it.
   - Every shot keeps secondary motion (`drift`, `breathe`, parallax, a ticking element); the end is a live lockup (the name settles within 1 s, then a glow pulse or drift keeps going), never a dead hold. Final text stays legible and whole.
4. Assets: use the kit (`import {Cup, Card, Pin} from '@/assets'`) or `assets.json` + `npm run art -- examples/samples/<slug>/assets.json`. Never an icon library, never ad-hoc shapes for heroes. Mark the hero element `data-subject="<name>"` so the render audit reports it when it is cropped (`element_cropped`) or covers text (`subject_overlaps_text`); labels that belong to the object go inside that element. See `../frameforge-best-practices/references/assets.md`. Titles, lower thirds, counters, cards, tickers, charts, code and diagrams come from the block catalogue (`import {GlyphRise, LowerThird, BarChart} from '@/blocks'`, `../frameforge-blocks/SKILL.md`), never hand-written. A 3D hero or turntable: `3d.json` + `npm run blender` + `<ImageSequence>` (`../frameforge-3d/SKILL.md`). An algorithmic background: `<Generative>` (`../frameforge-generative/SKILL.md`).
5. A spoken film is narration-first: write `narration.json`, run `npm run voice`, read `narration.timing.json`, then build scenes on `useNarration` with `<Voiceover>` and `<Subtitles>` (`../frameforge-voice/SKILL.md`). Write `Spot.tsx` as a pure frame function with motion probes and `MotionSound` maps (`../frameforge-best-practices/references/motion.md`, `sound.md`); every cut is a seam in one current (`<Seam>`, `cutTheCurve`, `../frameforge-best-practices/references/seams.md`); `entry.tsx` registers the composition; add one import and one `<Composition>` line to `examples/samples/index.tsx`.
6. Generate sound: `npm run score -- examples/samples/<slug>/audio.json`.
7. Check and render as `frameforge-check` and `frameforge-render` say. Report what you measured and what you did not.
