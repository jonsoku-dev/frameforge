# Create a film

1. Repository root = two folders above this file (it holds `package.json` with `"name": "frameforge-local"`). Run `npm install` once if `node_modules` is missing.
2. Pick a slug (kebab-case) and copy `examples/samples/_template/` to `examples/samples/<slug>/`; rename `template.audio.json` to `audio.json` and set `"slug"`.
   Not inside the engine repository: run `frameforge init <dir>` once (or `node <engine>/bin/frameforge.mjs init <dir>`), then `frameforge new <slug>` inside it. That copies the template to `films/<slug>/`, renames the id to the PascalCase slug, and registers it in `films/index.tsx`; use `frameforge score|art|lint|render|studio|check` there instead of the npm scripts, with `films/<slug>` in place of `examples/samples/<slug>`.
3. Engine brief first: fill `brief.md` (copied with the template) before anything else. `## Request` is the user's request verbatim, unchanged. `## Intent ledger` has one row per clause, split so no word of the request is left over: the clause quoted exactly, its kind (`must`, `forbid`, `taste`, or `implied` for what the genre expects but nobody said, such as a name card in a showreel or a product reveal in a launch), the concrete engine means (a `<Shader>` preset, a block, a seam, an `audio.json` field, a size, fps or duration) and where it is verified (a Structure row and frame range, or a check). `## Engine translation` restates the film in engine vocabulary: concept, world, hero, palette, families and signature moves from `showreel.md`, duration, size, fps, audio. It may add detail but never contradicts, weakens or drops a must or forbid row; taste rows hold unless they conflict with a must; implied rows never override a stated clause; when the request is open ("you pick") commit to bold choices and label them `Decision:`, not as the user's intent. `## Gaps` lists what the engine cannot do or what conflicts, with the substitute chosen (`None.` when empty); nothing is dropped silently. Run `node bin/frameforge.mjs brief-check <slug>` (or `npm run brief-check -- examples/samples/<slug>`) until it prints PASS: it fails on an empty request, a row without means or verification, a request sentence no clause covers (naming it and the missing words), and seconds, WxH or fps in a must clause that differ from `entry.tsx`.
4. Write `prompt.md` next, following the Engine translation, in the template's six sections: Inputs, Direction (it opens with a `Concept:` paragraph, below) with a `Banned:` line, Structure on the beat grid (absolute frames, what the hero becomes and what the camera fills in each row), Build, Gotchas, Start. Show the Structure table before writing code. Rules: `docs/samples/rules.md` 기획 구조; worked example: `examples/samples/morph-ui/prompt.md`.
   - Concept first, before the Structure table: one `Concept:` paragraph in Direction with the single idea, the world it happens in, one hero subject that recurs and changes state, a palette derived from the concept (not a default; named palettes in `showreel.md`), three to five signature moves chosen for this concept from at most two families of the showreel menu, and how motion enacts the words (each line of copy gets a behaviour that does what it says: `../frameforge-best-practices/references/kinetic-type.md`). Self-check: if your scene list could be pasted into another prompt's film unchanged, start again.
   - Motion graphics means spectacle and continuity by default: every second shows at least one active effect or transformation, the camera never fully stops, scenes morph into each other (continuous morph is the default grammar for showreels, launches and idents), the frame is layered (foreground type, an effect, a textured background) and the technique changes on every beat. Restraint (a calm explainer) only when the request asks for it. The menu of families, palettes and components: `../frameforge-best-practices/references/showreel.md`; it is a menu, never a fixed scene list.
   - The hook: frame 0 to 30 of every film is a striking, frame-filling image or action (a macro crop of the hero, a full-bleed texture, the first pour already moving, a headline larger than the frame). Never a small mark, dot or logo on an empty field; frame-check counts that second as empty or huddled.
   - A process request: the composition evolves step by step (the camera reframes, a tracker fills, completed items accumulate, the card moves); never the same layout repeated across steps.
   - A process request: hero props are illustrated objects, not icons (recognisable silhouette, a label or detail, highlight and shadow, one outline weight; kit `Bottle`, `Glass` or drawn in `assets.tsx`), and tools are shown in use: the bottle tilts and pours from its own neck (`<Stream from={bottleNeck({size, tilt, x, y})}>`).
   - A process request (recipe, how it works, assembly, data flowing): every Structure row names a cause and its visible effect in the same frames (the bottle tilts and `<Stream>` pours while the level rises past labelled marks; the arrow carries the item into the box). From the first frame of a pour the level and the count both change in the frames where the stream is visible; a quantity never sits at zero under a visible stream. The subject stays whole in frame; quantities are labelled on the object.
   - A showreel, reel or brand film: pick one or two families from the showreel menu that fit the concept (type-led, geometric/Bauhaus, 3D hero, cosmic/scientific, retro/CRT, data) and name the concept's signature moves with the component that makes each. Never default to streaks, iris, liquid type, cube field or tunnel; use one only when the concept's world calls for it. A film that uses one technique throughout reads as a template; a film that uses every technique reads as the same template as every other film.
   - A lit 3D hero without assets (a planet, a star, a scan-line or glossy bust, a torus knot, light orbits) comes from the hero `<Shader>` presets `planet`, `sun`, `sliced`, `orbits` (`docs/reference/generative.md`). Type-led and Bauhaus films use the kinetic blocks `WordBeat`, `Thread`, `TextField`, `WhipPan`, `BauhausMosaic`, `Toggle` (`../frameforge-best-practices/references/kinetic-type.md`).
   - No corner readouts (timecode, frame counter, scene number, BPM, REC): they read as an AI template. The render audit reports small corner text over half the film as `corner_hud`; a concept that is literally a camera or broadcast opts in with `data-hud="allow"` and a reason in `prompt.md`.
   - No blank transition frames: a cut, wipe or whip never leaves a full frame of one flat colour or a full blur for more than two frames (frame-check `featureless`).
   - For image-like texture (macro, liquid, tunnel, grain) use `<Shader>` presets, never stock images.
   - "Go crazy", "go all out", "wow" or "make it insane": maximal density. A new technique on every beat (no technique twice in a row), at least one full-frame image-like texture moment (a macro crop, `<Generative system="halftone">` or grain over a photographic-feeling generative field), cuts on the beat, and one cinematic camera move (a push through, an orbit or a fly-through in 3D perspective). Every word stays legible: whole words only, no garbled states, headlines held 1.2 s.
   - Invented names (clients, products, cities, people) are plausible and specific: "Halden Coffee", "Mira Osei", "Northfield Transit", never "Client A", "Brand X" or "Company 1". They stay fictional and the Inputs say so.
   - Sample data is labelled once, small, in the film's language: one footnote on the beat ("Sample data" in English, "サンプルデータ", "샘플 데이터"), not a tag on every stat. Blocks take `example` as `true | false | 'text'` and pick Sample, サンプル or 예시 from `lang` or the script of their own copy; pass `example={false}` on every block but the one that carries the tag, or on all of them when a footnote does it.
   - Every shot keeps secondary motion (`drift`, `breathe`, parallax, a ticking element); the end is a live lockup that arrives within the last 1.5 s and keeps moving (camera drift, a light sweep, particles, the hero still turning), never a dead hold; frame-check fails a final 2 s with a motion share under 0.5. Final text stays legible and whole.
5. Assets: use the kit (`import {Cup, Card, Pin} from '@/assets'`) or `assets.json` + `npm run art -- examples/samples/<slug>/assets.json`. Never an icon library, never ad-hoc shapes for heroes. Mark the hero element `data-subject="<name>"` so the render audit reports it when it is cropped (`element_cropped`) or covers text (`subject_overlaps_text`); labels that belong to the object go inside that element. See `../frameforge-best-practices/references/assets.md`. Titles, lower thirds, counters, cards, tickers, charts, code and diagrams come from the block catalogue (`import {GlyphRise, LowerThird, BarChart} from '@/blocks'`, `../frameforge-blocks/SKILL.md`), never hand-written. A 3D hero or turntable: `3d.json` + `npm run blender` + `<ImageSequence>` (`../frameforge-3d/SKILL.md`). An algorithmic background: `<Generative>` (`../frameforge-generative/SKILL.md`).
6. A spoken film is narration-first: write `narration.json`, run `npm run voice`, read `narration.timing.json`, then build scenes on `useNarration` with `<Voiceover>` and `<Subtitles>` (`../frameforge-voice/SKILL.md`). Write `Spot.tsx` as a pure frame function with motion probes and `MotionSound` maps (`../frameforge-best-practices/references/motion.md`, `sound.md`); every cut is a seam in one current (`<Seam>`, `cutTheCurve`, `../frameforge-best-practices/references/seams.md`); `entry.tsx` registers the composition; add one import and one `<Composition>` line to `examples/samples/index.tsx`.
7. Generate sound: `npm run score -- examples/samples/<slug>/audio.json`.
8. Check and render as `frameforge-check` and `frameforge-render` say; `frameforge check <out.mp4> --film <slug>` includes the `brief` row.
9. Self-review before delivery: re-read the ledger against the contact sheet, the frames and the check output. The report lists every must and forbid clause, quoted, with PASS or FAIL and the evidence (frame range or check), repeats every Gap with its substitute, and says what you measured and what you did not.
