# Create a film

1. Repository root = two folders above this file (it holds `package.json` with `"name": "frameforge-local"`). Run `npm install` once if `node_modules` is missing.
2. Pick a slug (kebab-case) and copy `examples/samples/_template/` to `examples/samples/<slug>/`; rename `template.audio.json` to `audio.json`, set `"slug"`, and change `./template.audio.json` to `./audio.json` in `Spot.tsx`.
   Not inside the engine repository: run `frameforge init <dir>` once (or `node <engine>/bin/frameforge.mjs init <dir>`), then `frameforge new <slug>` inside it. That copies the template to `films/<slug>/`, applies every rename and registers it in `films/index.tsx`; use `frameforge score|art|lint|render|studio|check` there instead of the npm scripts, with `films/<slug>` in place of `examples/samples/<slug>`.
3. Engine brief first: fill `brief.md` (copied with the template) before anything else. `## Request` is the user's request verbatim, unchanged. `## Intent ledger` has one row per clause, split so no word of the request is left over: the clause quoted exactly, its kind (`must`, `forbid`, `taste`, or `implied` for what the genre expects but nobody said, such as a name in a showreel or a product reveal in a launch), the concrete engine means (the rendering technique you will write, an `audio.json` field, a size, fps or duration) and where it is verified (a Structure row and frame range, or a check). `## Engine translation` restates the film in engine vocabulary: concept, world, hero, palette, rendering layers, duration, size, fps, audio. It may add detail but never contradicts, weakens or drops a must or forbid row; taste rows hold unless they conflict with a must; implied rows never override a stated clause; when the request is open ("you pick") commit to bold choices and label them `Decision:`, not as the user's intent. `## Gaps` lists what the engine cannot do or what conflicts, with the substitute chosen (`None.` when empty); nothing is dropped silently. Run `node bin/frameforge.mjs brief-check <slug>` (or `npm run brief-check -- examples/samples/<slug>`) until it prints PASS: it fails on an empty request, a row without means or verification, a request sentence no clause covers (naming it and the missing words), and seconds, WxH or fps in a must clause that differ from `entry.tsx`.
4. Write `prompt.md` next, following the Engine translation, in the template's sections: Inputs, Direction (it opens with a `Concept:` paragraph) with a `Banned:` line, Structure on the beat grid (absolute frames), Build (the rendering plan), Second pass, Gotchas. Show the Structure table before writing code. Rules: `docs/samples/rules.md` 기획 구조.
   - Concept first: one paragraph with the single idea, the world it happens in, one hero that recurs and changes state, a palette derived from the concept (never a default), the signature moves this concept needs, and how motion enacts each line of copy (`../frameforge-best-practices/references/kinetic-type.md`). Self-check: if the scene list could be pasted into another prompt's film unchanged, start again. Nothing in this repository's docs or examples is a scene, palette or line to reuse.
5. Build by film kind.
   - **Motion graphics** (showreel, reel, ident, launch, promo, brand film, "show off", "go crazy"): bespoke-first. Write the film's own rendering code for its concept: a fragment shader (`<Shader frag>` with your GLSL), a 2D canvas you paint (`<Canvas2D draw>`), a three.js scene (`<ThreeCanvas>`, `<Bloom>`), DOM type over them. You own the camera, the easing, the particle systems and the type animation. Helpers and their contracts: `../frameforge-best-practices/references/bespoke.md`. The bar is `../frameforge-best-practices/references/showreel.md`; read it before the Structure table and again at the second pass. Blocks, kit motifs and shader presets are not the path for these films.
   - **Explainer, process, captions, charts, data film, a calm film the request asks for**: the utilities appendix (`../frameforge-best-practices/references/utilities.md`) lists blocks, the motif kit, assets, shader presets, narration and captions you may use; bespoke code is still allowed wherever it serves better.
   - Every film: one hero marked `data-subject="<name>"` when it is a DOM element; type in Google Fonts (`googleFont`), never a system font; no corner readouts (timecode, frame counter, scene number, BPM, REC; the audit reports `corner_hud`); no technique or scene names as on-screen labels; no blank transition frames (frame-check `featureless`); invented names stay fictional, plausible and specific, and the Inputs say so; sample numbers carry one small footnote in the film's language.
   - The first second is already a striking, frame-filling, moving image. Every cut lands in motion and the film keeps one dominant direction (`../frameforge-best-practices/references/seams.md`). The end is a lockup that arrives within the last 1.5 s and is still moving (frame-check fails a final 2 s with a motion share under 0.5); a poster is a separate still render, never a held end.
6. `Spot.tsx` is a pure function of `useCurrentFrame()`; cuts on bar lines and accents from `beatsFromSpec(spec, fps)`; report big moves with `<MotionProbe>` and declare `<MotionSound>` (`../frameforge-best-practices/references/motion.md`, `sound.md`). A spoken film is narration-first (`../frameforge-voice/SKILL.md`). `entry.tsx` registers the composition; add one import and one `<Composition>` line to `examples/samples/index.tsx`.
7. Generate sound: `npm run score -- examples/samples/<slug>/audio.json`.
8. Second pass (mandatory): render a contact sheet with one cell per beat or scene (`npm run render -- <entry.tsx> <Id> renders/samples/<slug>-sheet.png --frames ...`), critique every cell against `showreel.md`'s bar and self-checks in writing in `prompt.md` (Second pass), name the two weakest scenes and remake them (new technique, not a tweak), render the sheet again, and only then the final render.
9. Check and render as `frameforge-check` and `frameforge-render` say; `frameforge check <out.mp4> --film <slug>` includes the `brief` row. Canvas and shader text is not in the audit: check its size, margin and contrast on the sheet.
10. Self-review before delivery: re-read the ledger against the contact sheet, the frames and the check output. The report lists every must and forbid clause, quoted, with PASS or FAIL and the evidence (frame range or check), repeats every Gap with its substitute, and says what you measured and what you did not.
