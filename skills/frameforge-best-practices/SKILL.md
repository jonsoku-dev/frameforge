# Frameforge best practices

This skill holds every rule; the task skills (`frameforge-create`, `frameforge-assets`, `frameforge-audio`, `frameforge-render`, `frameforge-studio`, `frameforge-check`) and the lever skills (`frameforge-blocks`, `frameforge-voice`, `frameforge-3d`, `frameforge-generative`) are entry points into it. The repository root is two folders above this file.

The repository root is the folder that holds `package.json` with `"name": "frameforge-local"`. Everything below is relative to it. Read only the reference file your step needs.

## The one workflow

1. **Engine brief** → before any concept, fill `examples/samples/<slug>/brief.md`: `## Request` verbatim, `## Intent ledger` (one row per clause, every word of the request covered: quoted clause, kind `must`/`forbid`/`taste`/`implied`, engine means, where it is verified), `## Engine translation` (the film in engine vocabulary; adds detail, never contradicts, weakens or drops a must or forbid; open choices labelled `Decision:`), `## Gaps` (what the engine cannot do and the substitute; `None.` when empty). `node bin/frameforge.mjs brief-check <slug>` must PASS. The user's intent is the ledger; every later step follows the translation.
2. **Plan** → write `examples/samples/<slug>/prompt.md` from the Engine translation in six sections: Inputs, Direction (a `Concept:` paragraph first: the single idea, its world, one recurring hero, a palette derived from the concept, 3-5 signature moves from at most two families of `references/showreel.md`, how motion enacts the words; then taste and a `Banned:` line), Structure (BPM, bars, one row per beat or bar in absolute frames), Build (fps, springs, camera, blur, beat contact sheet), Gotchas, Start (show the state list on the beat grid before code). Rules: `docs/samples/rules.md` is binding. Template: `examples/samples/_template/`.
3. **Assets** → never draw hero shapes ad hoc and never use an icon library (the one exception: `lucide-react` markers in explainer callouts over real screens). Before hand-writing a title, lower third, counter, card, chart, code panel or diagram, take it from the block catalogue (`import {LowerThird, BarChart} from '@/blocks'`, `frameforge-blocks`). A rendered 3D hero or turntable comes from `3d.json` and `<ImageSequence>` (`frameforge-3d`); an algorithmic background from `<Generative>` (`frameforge-generative`). Otherwise use the motif kit (`import {Cup, Card, Pin} from '@/assets'`, parametric: `size`, `ink/accent/soft/paper`, `stroke`, `radius`, `draw`, `parts`) or declare `examples/samples/<slug>/assets.json` with `intent` sentences and run `npm run art -- examples/samples/<slug>/assets.json`; the resolver picks host-placed files → your own image skill (`FRAMEFORGE_IMAGE_COMMAND`) → Openverse CC0 SVG → the kit, and `<Art src="/assets/generated/<slug>/<name>.svg" draw />` plays it. Details: `references/assets.md`.
4. **Motion** → motion graphics means spectacle and continuity by default: every second shows an active effect or transformation, the camera never fully stops, scenes morph into each other, the frame is layered (type, effect, textured background) and the technique changes on every beat; restraint only when the request asks for a calm film (`references/showreel.md` is a menu of families, palettes and components, never a fixed scene list: if your scene list could be pasted into another prompt's film unchanged, start again; `references/kinetic-type.md` for type that enacts its words). `Spot.tsx` is a pure function of `useCurrentFrame()`; `interpolate`, `spring`, `Sequence`, wipes and glyph rises; pick a grammar (continuous morph is the default for showreels, launches and idents): continuous morph (one hero changes state, the camera reframes each state; 60 fps, `springTrack`, `<CameraMotionBlur>` with probes outside it) or joined scenes; sizes from 구성 최소치; text inside the safe area; secondary motion in every shot (`drift`, `breathe`, parallax, a ticking element) so no 0.5 s window is frozen; text reveals show only whole words (no scramble); a process shows cause and effect together (`<Stream>`, labels on the object, the subject whole and marked `data-subject`), with illustrated props in use and a layout that moves on at every step; end on a live lockup (arrives within the last 1.5 s and keeps moving: camera drift, light sweep, particles; frame-check fails a final 2 s under 0.5 motion share) or an exact loop; no transition leaves three flat or fully blurred frames (frame-check `featureless`). `references/motion.md`. Every cut is a seam: one dominant direction per film, the exit vector decides the entry vector, cut mid-motion on both sides (`cutTheCurve`, `zoomThrough`, `<Seam>`; `references/seams.md`). Beats come from the music grid (`beatsFromSpec(audioSpec, fps)`: cuts on bar lines, pulses on hits).
5. **Sound** → `audio.json` next to the Spot (sections on bar lines, hits on visual events, `sfx[]` with `intent` sentences); in the Spot report animated values with `useMotionSound`/`<MotionProbe>` and declare `<MotionSound role src quiet />`; the engine derives move/land/appear sounds, ducks music under them, and refuses dense hand-placed effects. `references/sound.md`. A spoken film is narration-first: `narration.json` → `npm run voice` → `narration.timing.json` → scenes on `useNarration`, `<Voiceover>` (music ducks under it) and `<Subtitles>` as an overlay (`frameforge-voice`, `references/captions.md`).
6. **Check** → render a contact sheet of the check frames (`--frames`, own `FRAMEFORGE_PORT` if another render runs), look at every cell; `npx tsc --noEmit`; `npm test`; `npm run lint:video -- examples/samples/<slug>/entry.tsx`; then render `npm run render -- examples/samples/<slug>/entry.tsx <Id> renders/samples/<slug>.mp4` and run `node bin/frameforge.mjs check renders/samples/<slug>.mp4 --film <slug>` (frame-check, flash-check, seam-check on the render's `.motion.json`, narration-check when the film speaks, brief). Before delivery re-read the ledger against the frames and the check output; the report lists each must and forbid clause with PASS or FAIL and repeats every Gap. The renderer fails on clipped text, dense effects and mixed frame sizes and prints an `{"audit": [...]}` line for text outside the safe area, overlaps, low contrast and small text; fix the cause, never bypass. `references/checks.md`.
7. **Studio** → `VIDEO_ENTRY=examples/samples/index.tsx npm run dev` (port 4317) shows every registered composition with the process log, tuning variables and renders. Register new films in `examples/samples/index.tsx`.

## Hard rules

- Deterministic frames only: no `Math.random`, wall clock, timers, CSS animations. Use `random(seed)`.
- Copy in the brief's language; fictional brands with plausible, specific names (never "Client A"); sample numbers labelled once, small, in the film's language ("Sample data", "サンプルデータ", "샘플 데이터"; blocks pick the word from `lang` or their copy); real screens only in explainers, unmodified, with trademark notes in `prompt.md`.
- No shared audio or asset files committed: everything under `public/audio/generated/` and `public/assets/generated/` is produced on demand from the specs.
- Never show text in a garbled intermediate state: a reveal shows only whole glyphs at full opacity or none (word-level mask rises of ≤ 8 frames are the allowed motion). No scramble effects.
- Effects are the default toolkit, one line each in `prompt.md` Build: `<Glow>`, `<ChromaticShift>`, `<Scanlines>`, `<VhsGlitch>`, `<Extrude>`, `<Shader>` presets (texture: `iris`, `tunnel`, `liquid`, `grainField`, `gradientMesh`, `streaks`, `cubeField`; raymarched backgrounds (and the hero fallback without Blender): `planet`, `sun`, `sliced`, `orbits`; a 3D hero itself is a Blender shot with a `look` (`frameforge-3d`); never stock images), the kinetic type blocks (`WordBeat`, `Thread`, `TextField`, `WhipPan`, `BauhausMosaic`, `Toggle`), grain or halftone, a vignette, purposeful particles (never dust). Use only what the concept calls for, from at most two families. Corner readouts (timecode, frame counter, scene number, BPM, REC) are off by default; the audit reports them as `corner_hud` unless the film opts in with `data-hud="allow"` and a reason. Still banned: an icon library for heroes, off-palette colours, clip-art, stock gloss, an effect that leaves the final text unreadable.
- Write what you did not verify in `prompt.md` and in your report. Never drop a request clause silently: it is a ledger row or a Gap.

## Commands

| Need | Command |
| --- | --- |
| Music + effects for one film | `npm run score -- examples/samples/<slug>/audio.json` |
| Assets for one film | `npm run art -- examples/samples/<slug>/assets.json` |
| Measure the music | `python3 scripts/assets/score-report.py public/audio/generated/<slug>/music.wav --spec examples/samples/<slug>/audio.json` |
| Render | `npm run render -- <entry.tsx> <Id> <out.mp4> [--frames 30,60] [--concurrency 3] [--frame-range a-b] [--pipe] [--check-idempotent]` |
| Contact sheet | `npm run render -- <entry.tsx> <Id> <sheet.png> --frames 30,120,240` |
| Lint | `npm run lint:video -- <entry.tsx>` |
| Composition check | `npm run frame-check -- <out.mp4>` |
| Flash check | `node scripts/flash-check.mjs <out.mp4>` |
| Compare two renders | `node scripts/snapshot-diff.mjs --against old.mp4 new.mp4 [--threshold 40]` |
| Voice for a narrated film | `npm run voice -- examples/samples/<slug>/narration.json` then `npm run narration-check -- examples/samples/<slug> --prompt examples/samples/<slug>/prompt.md` |
| Seams of a render | `npm run seam-check -- renders/samples/<slug>.mp4.motion.json --prompt examples/samples/<slug>/prompt.md` |
| 3D shots and CC0 models | `npm run blender -- examples/samples/<slug>/3d.json [--frames 0-1]`, `npm run models -- examples/samples/<slug>/models.json` |
| Beats of an external track | `npm run beats -- <audio file> --out beats.json` |
| Intent ledger of a film | `node bin/frameforge.mjs brief-check <slug>` |
| Every check in one table | `node bin/frameforge.mjs check <out.mp4> --film <slug>` |
| Other containers | `npm run render -- <entry.tsx> <Id> out.webm\|out.mov\|out.gif\|frames/ [--transparent] [--scale 2] [--crf 18]` |
| Link the skills into agent folders | `npm run skill:install` |
