# 샘플 영상 제작 규칙

모든 샘플은 이 규칙을 지킨다. 어기면 렌더가 실패하거나 검수에서 떨어진다.

## 파일

- `examples/samples/<slug>/Spot.tsx`: 컴포지션. `useCurrentFrame()`은 루트에서 한 번. 장면 컴포넌트는 `frame`을 props로 받는다. 예외는 `<CameraMotionBlur>` 하나다. 블러의 복사본은 정지된 하위 트리라서, 그 안의 그림 루트에서 한 번 더 불러 소수 프레임을 받는다(`examples/samples/morph-ui/Spot.tsx`의 `Picture`).
- `examples/samples/<slug>/entry.tsx`: 이 컴포지션 하나만 `registerRoot`로 등록. 장면 ID는 PascalCase slug.
- `examples/samples/<slug>/audio.json`: 소리 사양(아래 소리 절). `assets.json`(그림 에셋 해결 사양)과 `assets.tsx`(직접 그린 에셋)는 필요할 때만.
- `examples/samples/<slug>/brief.md`: 엔진 브리프. 기획보다 먼저 쓴다(아래 "기획 구조"의 0번). 템플릿은 `examples/samples/_template/brief.md`.
- `examples/samples/<slug>/prompt.md`: 기획. 아래 "기획 구조" 절의 칸(입력, 방향, 구조, 빌드, 두 번째 패스, 함정, 시작)을 채운다. 템플릿은 `examples/samples/_template/prompt.md`.

## 기획 구조

장면표만 있는 기획은 "무엇을"만 정하고 "어떤 취향으로"를 비워 둔다. 그 빈칸을 모델이 채우면 헤드라인과 카드를 컷으로 잇는 평범한 영상이 나온다. 잘 만든 모션 그래픽 프롬프트는 거의 모두 아래 칸들로 되어 있어서, `prompt.md`도 이 순서를 따른다. 그 앞에 요청을 옮기는 엔진 브리프가 온다.

0. **엔진 브리프(`brief.md`).** 사용자 요청을 그대로 두고 엔진에 맞게 옮긴다. 의도는 하나도 잃지 않는다. `## Request`에 요청 원문을 고치지 않고 붙인다. `## Intent ledger`는 요청의 절마다 한 행이다. 행은 따옴표로 그대로 옮긴 절, 종류(`must` 필수, `forbid` 금지, `taste` 취향, `implied` 장르가 당연히 기대하는 것. 예: 쇼릴의 이름 카드, 런칭의 제품 공개), 엔진 수단(셰이더 프리셋, 블록, 이음새, `audio.json` 필드, 크기·fps·길이), 확인 위치(구조 행과 프레임 범위, 또는 검사 이름)를 적는다. 절들을 합치면 요청의 모든 단어가 들어가야 한다. `## Engine translation`은 엔진 말로 다시 쓴 기획(컨셉, 세계, 주인공, 팔레트, `showreel.md` 계열과 대표 기법, 길이·크기·fps, 소리)이다. 구체성은 더해도 되지만 필수와 금지를 거스르거나 약하게 하거나 빼지 않는다. 취향은 필수와 부딪히지 않으면 지킨다. implied는 명시된 절을 이기지 못한다. "마음대로" 같은 열린 요청은 과감하게 정하고 `Decision:`으로 적어 사용자의 의도와 구별한다. `## Gaps`에는 엔진이 못 하는 것이나 서로 부딪히는 것과 고른 대안을 적는다(없으면 `None.`). 조용히 빼지 않고, 마지막 보고에서 사용자에게 다시 말한다. `node bin/frameforge.mjs brief-check <slug>`가 PASS여야 다음으로 간다. `brief.md`가 없는 작품은 이 단계 전에 만든 것으로 보고 SKIP한다. `frameforge new`와 템플릿 복사는 늘 `brief.md`를 가져오므로 새 작품은 채울 때까지 FAIL이다.
1. **입력.** 시작 전에 정해야 할 것. 상태 목록, 색, 곡의 BPM, 가상 브랜드 이름. 사용자에게 받을 것과 기본값을 적는다.
2. **방향.** 한 문단으로 쓰는 취향. 기준이 되는 수준, 주인공 하나, 카메라가 하는 일, 글꼴, 이징 성격을 적는다. 끝에 `금지:` 한 줄을 둔다. 금지에는 이 작품이 빠지기 쉬운 상투를 이름으로 적는다("헤드라인 + 카드 세 장 나열", "페이드로만 등장", "템플릿처럼 보이는 것", "빈 박자").
3. **구조.** 박자 단위. 첫 줄에 `BPM, 마디 수, 박마다 무엇이 일어나는가`를 쓰고, 표의 각 행은 박 또는 마디 하나이며 절대 프레임 범위를 갖는다. 행마다 "주인공이 어떤 상태가 되는가"와 "카메라가 무엇을 채우는가"를 적는다. 연속 모핑 영상은 행이 컷이 아니라 상태 변화다. 그래서 `Cuts: none`(또는 `Cuts: 120, 300`) 한 줄로 실제 컷을 적고, seam-check는 표 대신 이 줄을 읽는다.
4. **빌드.** 이 작품의 기술 결정. fps, 스프링 방식, 카메라 계산, 모션 블러, 소리 배치, 그리고 전체 렌더 전에 "박마다 한 장" 콘택트 시트를 먼저 찍는다는 약속.
4b. **두 번째 패스(필수).** 첫 콘택트 시트의 칸마다 기준(`references/showreel.md`)에 대어 글로 비평하고, 가장 약한 장면 둘을 새 기법으로 다시 만들고, 시트를 다시 찍은 뒤에야 최종 렌더를 한다. 그 기록을 `prompt.md`의 Second pass 칸에 둔다.
5. **함정.** 이 종류의 영상에서 실제로 깨지는 것과 피하는 법. 만들면서 겪은 것을 추가한다.
6. **시작.** 코드를 쓰기 전에 무엇을 먼저 보여 주는가. 기본은 "박자 격자 위의 상태 목록을 먼저 보이고 확인받는다"이다.

기존 칸(목적, 가상 브랜드, 형식, 색, 글꼴, 크기, 소리, 검사 프레임)은 입력과 빌드 안에 둔다.

## 결정성

- 모든 값은 프레임 번호의 함수. `Math.random`, `Date`, `performance.now`, state, effect, CSS transition/animation 금지. 난수는 `random('seed')`, 이어지는 난수열은 `rng('seed')`. 캔버스와 셰이더도 프레임마다 처음부터 그린다(그리기 사이에 상태를 남기지 않는다).
- 같은 프레임을 두 번 그리면 같은 화면.

## 화면

- 1920×1080 또는 1080×1920, 10–30초. 30fps가 기본이다. 연속 모핑, 빠른 카메라, 모션 블러를 쓰는 작품은 60fps로 만든다(아래 모션 절). 검사 도구는 영상의 fps를 읽어 시간 기준을 초 단위로 맞춘다.
- 색은 최대 네 개(배경 둘, 강조 하나, 글자 하나). 팔레트 밖의 색은 쓰지 않는다.
- "모션 그래픽"(쇼릴, 릴, 아이덴트, 런칭, 프로모, 브랜드 영상, "자랑해 봐")은 직접 만든다. 이 컨셉을 위한 렌더링 코드(WebGL/GLSL 셰이더, 2D 캔버스, three.js, 그 위의 DOM 글자)를 작품이 쓰고, 카메라, 이징, 파티클, 글자 애니메이션을 작품이 정한다(`skills/frameforge-best-practices/references/bespoke.md`). 기준은 같은 모델이 맨손으로 짠 바이럴 코드 애니메이션 쇼릴을 이기는 것이다. 모든 프레임은 층이 있고 움직인다. 슬라이드 같은 정지, 납작한 카드, 화면에 기법·장면 이름 라벨, 모서리 HUD는 없다. 끝 록업은 계속 움직인다(`references/showreel.md`). 절제(차분한 설명 영상)는 요청이 그렇게 말할 때만 쓴다.
- 블록, 모티프 키트, 셰이더 프리셋, DOM 후처리 이펙트는 차분한 설명 영상, 자막, 차트, 데이터 영상이 필요로 할 때 쓰는 부록이다(`references/utilities.md`). 모션 그래픽 작품의 길이 아니다. 질감이 필요하면 스톡 이미지가 아니라 코드로 만든다.
- 컨셉이 먼저다. Structure 표 앞에 `Concept:` 문단 하나. 하나의 아이디어, 그것이 일어나는 세계, 다시 나오며 상태가 바뀌는 주인공 하나, 컨셉에서 나온 팔레트(기본값 아님), 대표 기법과 그것을 만드는 코드, 모션이 글의 뜻을 어떻게 행동하는지. 장면 목록을 다른 요청의 영상에 그대로 붙여 넣을 수 있으면 다시 시작한다. 저장소의 문서와 예제에 있는 장면, 팔레트, 문구는 가져다 쓰지 않는다.
- 모서리 수치(타임코드, 프레임 카운터, 장면 번호, BPM, REC)는 기본으로 쓰지 않는다. 렌더 감사가 영상의 절반 넘게 모서리에 남는 작은 글자를 `corner_hud`로 잡는다. 컨셉이 정말 카메라나 방송이면 `data-hud="allow"`와 이유를 적는다.
- 전환은 한 가지 평평한 색이나 완전히 흐린 화면을 2프레임 넘게 남기지 않는다(frame-check `featureless`). 끝 록업은 마지막 1.5초 안에 도착하고 계속 움직인다(카메라 드리프트, 빛 스윕, 파티클). frame-check는 마지막 2초의 motion share가 0.5 미만이면 실패한다.
- 품질을 지키는 금지는 그대로다. 주인공에 아이콘 라이브러리, 클립아트, 팔레트 밖의 스톡 광택(크롬 그라데이션, 렌즈 플레어 사진), 장식용 먼지 파티클, 프레임 테두리, 가짜 휴대폰 베젤, 얼굴, 보석. 이펙트는 마지막 글자를 읽을 수 없게 만들지 않는다.
- 글꼴은 Google Fonts에서 디스플레이 하나, UI 하나까지. `googleFont('Family', {weights: [...]})`를 모듈 맨 위에서 부르고, 캔버스의 `ctx.font`에도 같은 문자열을 쓴다. 시스템 글꼴(Helvetica, Futura, Arial 같은 기기 글꼴)에 기대지 않는다. 기기마다 다른 영상이 된다.
- 글자는 TV 세이프 영역 안. 가로 5%, 세로 5% 여백. 헤드라인은 짧은 변의 10% 이상(아래 구성 최소치 표와 같다).
- 글자 마스크는 블록의 `blockMask`(위 0.1em, 아래 0.4em, 좌우 0.3em 여유, `examples/samples/explainer-patterns`의 `Glyphs`도 같은 것을 쓴다). 글자 잉크가 마스크나 프레임 밖으로 나가면 렌더가 `Clipped text` 오류로 멈춘다. 일부러 넘치는 띠에는 `data-clip="allow"`.
- 실제 회사, 실제 제품, 실제 로고, 실제 수치 금지. 브랜드는 가상이며 `prompt.md`에 가상임을 적는다. 지어낸 이름(고객, 제품, 도시, 사람)은 그럴듯하고 구체적이다. "Client A", "Brand X"는 쓰지 않는다.
- 샘플 수치는 작품의 언어로, 작게, 한 번 표기한다. 통계마다 태그를 다는 대신 그 박에 각주 하나를 둔다. 영어 작품은 "Sample data", 일본어는 "サンプルデータ", 한국어는 "샘플 데이터"나 "예시". 블록의 `example`은 `true | false | '글자'`이고, 글자를 주지 않으면 `lang` 또는 블록 글자의 문자 체계에 따라 Sample, サンプル, 예시를 고른다. 태그를 맡은 블록 하나만 남기고 나머지는 `example={false}`로 끈다.

## 구성 최소치

화면이 비거나 요소가 작으면 사람이 콘택트 시트를 볼 때까지 아무도 모른다. 아래 숫자는 기계가 잡는다. 시작은 `examples/samples/_template/`을 복사한다(`SIZES` 표가 들어 있다).

- 글자를 한 자씩 `inline-block`으로 분해해 올릴 때 공백은 `'\u00A0'` 이스케이프로 넣는다(템플릿의 보이지 않는 NBSP 리터럴은 베껴 쓰다 보통 공백으로 바뀌어 사라졌다). 보통 공백만 든 inline-block은 너비 0으로 접혀 "아침,어디서시작하죠?"처럼 띄어쓰기가 사라진다(cafe-morning 초판에서 발생).
- 크기는 짧은 변 기준. 헤드라인 10% 이상(1080 기준 108px), 라벨 3.5% 이상(38px), 아이콘 6% 이상(65px), 장면의 주인공 형태 35% 이상(378px). 여백은 가로 5%, 세로 5%.
- 첫 1초는 화면을 채우는 강한 그림이나 움직임이다(주인공의 매크로 크롭, 화면 가득한 질감, 이미 시작된 붓기, 화면보다 큰 헤드라인). 빈 화면 위의 작은 점이나 로고 하나로 시작하지 않는다.
- 모든 장면에 화면을 채우는 물체가 하나 있다. 장면표의 각 행에 "무엇이 화면을 채우는가"를 적고, 답이 "배경"이면 그 행은 빈 화면이다.
- `npm run frame-check -- renders/samples/<slug>.mp4`가 PASS여야 한다. 마지막 1초(끝 정지, `--hold`로 바꿀 수 있다)는 빼고 잰다. 기준:
  - 빈 화면 없음. 배경색이 아닌 픽셀이 1% 미만인 프레임이 1초 넘게 이어지면 실패.
  - 작은 요소만 있는 화면 8% 미만. 잉크가 가로의 5% 이상 지나는 행이 짧은 변의 6% 높이만큼 연속하지 않는 프레임(헤드라인급 요소가 없는 프레임)의 비율.
  - 가운데 몰림 25% 미만. 잉크 상자가 가로 40% 미만이면서 세로 40% 미만인 프레임의 비율.
  - 얼어붙은 구간 1초 이하. 0.5초 전 프레임과 비교해 바뀐 픽셀이 0.2% 미만인 프레임은 얼어 있다. 그런 구간이 1초를 넘으면 실패한다. 초당 몇 px의 카메라 드리프트도 움직임으로 잡힌다(헤드라인이 있는 화면에서 1 px/s부터 잡혔다). `motion share`(움직이는 프레임 비율)와 옛 정지 지표(바로 앞 프레임과 비교한 `static`, `still share`)는 참고로 출력한다.
- 픽셀 면적(배경이 아닌 비율)은 참고로만 출력한다. 잘 만든 샘플도 중앙값이 3–4%라서 기준으로 쓰지 않는다. 기준값은 `renders/samples`의 열네 편으로 맞췄다(opus 샘플은 통과, 작은 요소와 빈 화면이 지적된 샘플은 실패).

## 에셋과 아이콘

- 모션 그래픽 작품의 주인공은 작품의 렌더링 코드가 만든다. 설명·과정 영상의 주 에셋(장면의 주인공 형태, 전환을 이어 주는 모티프, 카드 안의 그림)은 이 순서로 구한다. 1) 모티프 키트 `@/assets`(`import {Cup} from '@/assets'`, 46종, `src/assets/catalog.ts`). 2) `assets.json`에 `intent`를 적고 `npm run art`로 해결한 SVG를 `<Art>`로 그린다(`docs/guides/assets.md` 2절). 3) 둘 다 맞지 않을 때만 직접 그린다. 직접 그릴 때는 SVG `path`와 기본 도형으로, 한 작품 안에서 선 굵기 하나(짧은 변의 1.3–1.8%, 1080 기준 14–20px), 모서리 반지름 하나, 색 셋 안에서. 작은 아이콘도 같은 규칙으로 직접 그린다. 주인공을 축소한 형태가 가장 자연스러운 아이콘이다(컵이 주인공이면 카드 아이콘도 그 컵의 선으로).
- 직접 그린 에셋은 `assets.tsx`에 따로 두고 `docs/guides/assets.md`의 주 에셋 품질 기준(실루엣 테스트, 도형 4–9개와 특징 디테일, 선 시스템, 8px 그리드, 세트 일관성, 에셋 시트 검사)을 통과해야 한다. 에셋 작성과 애니메이션 작성은 분리할 수 있다(에셋은 강한 모델).
- 아이콘 라이브러리는 쓰지 않는다. 범용 아이콘은 그려 둔 주인공과 선 굵기·모서리·비례가 달라 붙여 넣은 티가 난다. 예외는 실제 화면 설명 영상의 콜아웃 마커뿐이다. 거기서는 가리키는 버튼의 아이콘을 알아보게 하는 것이 목적이라 `lucide-react`(ISC, 설치됨)를 써도 된다. 쓰면 `prompt.md`에 적는다.
- 그리는 법. 한 에셋은 도형 4–9개, 그중 하나는 특징 디테일. `viewBox`는 0 0 400 400처럼 정사각형, `pathLength={1}`을 두고 `strokeDasharray={1} strokeDashoffset={1 - draw}`로 프레임 함수에 따라 그려지게 하거나, 스프링 스케일로 튀어나오게 한다. 채움보다 선이 먼저이고, 채움은 accent/soft 한 가지. 아이콘 안에 글자를 넣지 않는다.
- 크기는 짧은 변의 4% 이상(1080 기준 44px 이상), 주인공은 35% 이상. 실제 브랜드 로고, 유료 세트, 네트워크에서 받는 아이콘 폰트는 금지.

## 모션

- 두 가지 문법 중 하나를 고르고 `prompt.md` 방향 칸에 적는다.
  - **연속 모핑.** 주인공 하나가 끊기지 않고 상태를 바꾼다(버튼 → 로더 → 체크 → 카드 → 차트). 크기, 모서리, 색이 바뀌고 안의 내용은 짧은 블러로 교체된다. 컷이 없으므로 "장면은 직전 장면의 물체에서 태어난다"가 저절로 지켜진다. 고급 모션 그래픽의 기본 문법이다.
  - **장면 잇기.** 장면을 컷으로 잇는다. 모든 컷은 seam이다(`references/seams.md`).
- 카메라는 강조 효과가 아니라 구도다. 상태마다 카메라가 줌·이동해 그 상태가 화면을 채우게 한다. 횟수 제한은 없다. 대신 카메라 값은 `<MotionProbe family="camera" axis="x|y|scale">`로 보고하고, 한 작품 안에서 흐름 방향을 하나로 유지한다.
- 움직임은 스프링으로. 오버슈트는 작게(댐핑 높게) 두고, 통통 튀는 이징은 쓰지 않는다. 목표가 여러 번 바뀌는 값은 바뀔 때마다 스프링 하나를 더한 합(`springTrack`)으로 계산해 프레임의 순수 함수로 남긴다. 탭 표시나 토글 손잡이처럼 늘어나는 요소는 앞 가장자리와 뒤 가장자리에 다른 스프링을 준다.
- 커서가 변화를 일으키면 실제 클릭과 드래그처럼 보이게 한다. 클릭은 눌림(scale 0.9)과 놓임, 드래그 중 값은 커서 위치에서 계산한다.
- 60fps 작품의 빠른 움직임에는 `<CameraMotionBlur shutterAngle={180} samples={4}>`를 장면 전체에 씌운다. 블러 안의 `MotionProbe`와 `Audio`는 보고되지 않으므로(정지된 복사본이다) 프로브와 소리는 블러 바깥, 루트에 둔다.
- 박마다 화면의 일이 바뀐다(차분한 설명 영상은 2–4초마다). 페이드만으로 등장하지 않는다.
- 과정 영상은 단계마다 구도가 진화한다. 카메라가 다시 잡고, 진행 표시가 차고, 끝난 항목이 쌓이고, 카드가 움직인다. 같은 레이아웃을 단계마다 되풀이하지 않는다.
- 과정 영상의 주인공 소품은 아이콘이 아니라 그린 물체다. 알아보는 실루엣, 라벨이나 디테일 하나, 하이라이트와 그림자, 선 굵기 하나. 도구는 쓰이는 모습으로 보인다(병은 기울어 자기 목에서 붓는다, `Bottle`과 `bottleNeck`).
- 모든 숏에 보조 움직임이 있다. 큰 변화 사이에도 어떤 0.5초 창도 얼어 있지 않다. 몇 px/s의 카메라 드리프트나 느린 확대(`drift(frame, {x, y, scale, period})`), 층 사이의 시차, 숨 쉬는 요소(`breathe(frame, period, amount)`), 째깍거리는 카운터나 진행 표시 중 하나 이상을 둔다. 끝은 살아 있는 록업이다. 마지막 글자가 읽히는 동안에도 글로우 맥동이나 드리프트 같은 이펙트가 계속된다. 완전히 멈춘 마지막 몇 초는 없다.
- 과정(레시피, 작동 원리, 조립, 데이터 흐름)을 보여 줄 때는 원인과 결과를 같은 화면에 동시에 보인다. 붓는 줄기와 차오르는 수위, 물건을 나르는 화살표. 줄기와 흐름은 `<Stream from to progress width color wobble>`으로 그린다. 붓기의 첫 프레임부터 줄기가 보이는 동안 수위와 수량 숫자가 함께 바뀐다. 줄기가 보이는데 수량이 0에 머물지 않는다. 주인공은 프레임 안에 온전히 두고, 수량 라벨은 물체 위에 붙인다(눈금, oz, %). 주인공 요소에 `data-subject="이름"`을 달면 렌더 감사가 프레임 밖으로 2% 넘게 나간 주인공을 `element_cropped`로, 글자를 20% 넘게 가린 주인공을 `subject_overlaps_text`로 잡는다. 물체에 붙은 라벨은 그 `data-subject` 요소 안에 두면 가림으로 세지 않는다. 일부러 프레임 밖에서 들어오는 주인공에는 `data-clip="allow"`.
- 글자는 깨진 중간 상태로 보이지 않는다. 드러나는 동안 화면의 글자는 온전한 글리프가 완전히 보이거나 아예 없다. 스크램블(무작위 글자가 섞였다 정답으로 바뀌는 효과)과 글자 반쯤 지운 교체는 쓰지 않는다. 허용되는 것은 단어 단위의 마스크 상승(`GlyphRise` 기본값, 한 단어가 한 기준선으로 8프레임 안에 올라온다), 단어 단위 타자(`Typewriter` 기본값), 블러를 거치는 `ZoomSwap`이다. 글자마다 길게 엇갈리는 상승(`by="glyph"`, 큰 `stagger`)은 피한다.
- 헤드라인은 다음 큰 변화 전에 1.2초 이상 읽힌다. 읽히는 동안에도 이펙트나 카메라는 움직인다. 끝은 둘 중 하나다. 살아 있는 록업(1초 안에 자리를 잡고, 그 뒤로도 글로우 맥동과 드리프트가 이어진다), 또는 마지막 프레임이 첫 프레임과 같은 루프(위치와 속도까지 같게). 루프 작품은 `frame-check --hold 0`으로 잰다.
- 하드컷은 1초에 한 번보다 자주 하지 않고, 검정과 흰색을 바로 붙여 컷하지 않는다(방송 플래시 기준). 풀프레임 플래시는 2프레임(60fps면 4프레임), 영상 전체에서 두 번까지.
- 카메라가 확대하는 요소에 `will-change`를 두지 않는다. 글자가 흐려진다. 모핑하는 상자 안에서 바뀌는 글자는 나가는 글자와 들어오는 글자에 따로 타이밍을 준다. 같이 두면 겹친다.

## 소리

- 공용 음원은 없다. 작품마다 자기 구조를 적은 스펙 `examples/samples/<slug>/audio.json`을 두고, 생성기가 그 스펙으로 `public/audio/generated/<slug>/music.wav`와 효과음을 만든다(형식은 `docs/audio-score.md`). 생성 파일은 커밋하지 않고 요청 시 다시 만든다. 개발 서버는 처음 요청될 때, 렌더러는 렌더 직전에 자동 생성한다.
- 스펙은 장면표를 그대로 따른다. 섹션 에너지는 훅에서 낮게, 본론에서 높게, 마지막 2초는 0.15 이하로 두어 음악이 사라지게 한다. `hits`는 화면의 사건(충돌, 이름 등장, 카운트 끝)과 같은 초에 둔다. 효과음은 아래처럼 움직임에서 받는다.
- 루트에 `<Audio src="/audio/generated/<slug>/music.wav" volume={0.9} />` 하나. 효과음은 `/audio/generated/<slug>/<name>.wav`.
- 효과음은 사양의 `sfx[]`에 `name`과 `intent`(무슨 소리인지 한 문장)와 `length`로 적는다. 생성기가 CC0 라이브러리 → 합성 순으로 소스를 정하고 `sfx.json`에 고정한다(`docs/audio-score.md` 효과음 절). 프리셋 이름만 적는 옛 방식은 폴백이다.
- 효과음은 손으로 프레임에 놓지 말고 움직임에서 받는다: 움직이는 값을 `useMotionSound`/`<MotionProbe>`로 보고하고 `<MotionSound role>`로 파일을 선언한다(`docs/audio-score.md` 움직임에서 나오는 소리). 엔진이 시작·착지·등장 사건을 찾아 밀도 규칙 안에서 넣는다. 손으로 놓는 `<Sequence><Audio/></Sequence>`는 움직임이 없는 사건(카운트 끝, 체크)에만.
- 효과음은 장면의 주된 사건 하나에만 붙인다. 글자 하나하나, 카드 하나하나에 붙이지 않는다. 간격 0.5초 이상, 어느 4초 안에서도 세 개까지, 음악 `hits`의 앞뒤 한 박 안에는 두지 않는다(타격은 음악이 낸다). 렌더러가 간격과 밀도를 검사해 어기면 렌더를 거부한다. 음량은 0.6 이하.
- 음악은 한 곡으로 들려야 한다. 섹션은 마디(4박) 단위로 두고, 15초 안에 섹션을 네 개 넘게 두지 않는다. 생성기는 악기 편성 변화를 마디선에 맞추고 필을 상승 경계에만 넣지만, 한 박짜리 섹션을 잇달아 두면 어떤 생성기도 이어 붙인 소리가 난다.

## 검사

- 먼저 자기 포트의 개발 서버와 CDP 스크립트로 키프레임 6장 이상을 찍고 본다. 색이 프레임을 채우는지, 글자가 잘리지 않는지, 직전 장과 다른지.
- `node bin/frameforge.mjs brief-check <slug>`가 PASS여야 한다(`frameforge check --film <slug>`의 `brief` 행). 넘기기 전에 의도 장부를 콘택트 시트, 프레임, 검사 결과와 다시 맞춰 보고, 보고에 필수·금지 절마다 통과·실패와 빈틈을 적는다.
- `npm run build`와 `npm test`가 통과해야 한다. `npm run lint:video -- examples/samples/<slug>/entry.tsx`에 `error`가 없어야 한다.
- 전체 렌더 `npm run render -- examples/samples/<slug>/entry.tsx <Id> renders/samples/<slug>.mp4` 뒤 `npm run frame-check`와 `node scripts/flash-check.mjs`를 돌린다. 다른 렌더와 동시에 돌리면 `FRAMEFORGE_PORT`로 렌더러의 Vite 포트(기본 4318)를 바꾼다.
