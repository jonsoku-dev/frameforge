# 같은 프롬프트, 아홉 모델 (2026-10-20)

같은 브리프를 아홉 모델에 그대로 주고, 교차 리뷰와 수정 라운드 없이 각 모델의 자체 검사만으로 끝낸 결과다. 모델이 혼자 어디까지 뽑는지 보는 실험이라 품질 차이가 그대로 남아 있다. 브리프 원문은 `.scratch/compare/brief-motion.md`(공통 규칙은 `.scratch/samples/brief-common.md`, `rules.md`). `.scratch/`는 gitignore된 로컬 폴더라 이 브리프 파일들은 저장소에 없다. 결과물은 `examples/samples/cmp-motion-<model>/`, 렌더는 `renders/samples/cmp-motion-*.mp4`, 시트는 `cmp-motion-*-sheet.png`, 15프레임 간격 스트립은 `cmp-motion-*-strip.png`. 스튜디오(`VIDEO_ENTRY=examples/samples/index.tsx npm run dev`)의 목록에도 전부 있다.

눈으로 본 판정(시트 8장 기준, 좋은 순):

1. **Fable 5.1**: 흩어지는 점 → 쌓이는 코인 → 카드 → 약속 → 이름. 네 장면이 한 물체로 이어지고 글자 크기와 여백이 TV 기준에 맞는다. 카드의 "예시 2,000,000원"까지 읽힌다.
2. **Opus 4**: 슬롯에서 떨어지는 코인이 전환의 코인 탑이 된다. 이야기가 가장 분명하다. 카드 03의 진행 막대, 이름 아래 밑줄까지 마감이 꼼꼼하다.
3. **gpt-5.6-terra**: 깔끔하고 균형 잡힌 카드 셋, 약속 장면의 원과 막대. 전환의 "한 번만 정하면"이 브리프의 코인 연속성 대신 쌓인 접시로 대체됐지만 어색하지 않다.
4. **Grok 4.7**: 링 코인과 곡선 그래프, 카드 셋을 세로 띠 셋으로 푼 선택이 독특하다. 약속 장면이 흰 글자 하나뿐이라 10–13초가 밋밋하다.
5. **Grok 4.7 build-fast**: 선 위를 구르는 코인과 언덕 그래프가 보기 좋다. 카드 셋이 두 번(들어오는 중, 완성)으로 나뉘어 시간을 쓰고, 이름 장면이 평범하다.
6. **gpt-5.6-luna**: ₩ 코인과 상승선, 카드 셋, 이름 뒤의 원. 구성은 맞지만 훅의 작은 글자(`놓치지 않게`)가 코인에 겹친다.
7. **Sonnet**: 코인이 납작한 알약 모양이고, 카드가 들어오는 장면에서 셋째 카드가 작게 떨어져 있다. 전체는 규칙대로다.
8. **Haiku**: 흰 원 하나와 글자. 전환의 코인 탑이 세 줄 막대로 축소됐고, 이름 장면에 밑줄·태그라인이 늦게 온다. 틀리진 않지만 밋밋하다.
9. **gpt-6-luna**: 카드 위를 가로지르는 선이 아이콘과 겹치고(규칙 위반: 요소 겹침), 전환 장면의 글자가 코인에 눌린다. 자체 검사가 이것을 잡지 못했다.

## 읽는 법

- 자동 검사(플래시, 음량, 프레임 검사)는 아홉 모델이 모두 통과했다. 통과가 품질을 뜻하지 않는다는 것이 이 실험의 결론이다. gpt-6-luna의 모션 샘플은 thin 0.00, huddled 0.00으로 수치상 가장 좋지만 눈으로는 가장 나쁘다.
- 자체 검사만으로는 요소 겹침(gpt-6-luna)이 남는다. 저장소에 없는 웹사이트 편에서는 글자 잘림과 띄어쓰기 누락도 남았다. 교차 리뷰와 수정 라운드(`README.md`의 제작 과정)가 왜 필요한지 보여 준다.
- 효과음은 이 실험이 끝난 뒤에 규칙이 바뀌었다(`rules.md` 소리 절: 0.5초 간격, 4초에 셋은 렌더러가 검사하고, 타격 근처 금지는 규칙이다). 여기 샘플들은 옛 규칙으로 썼고 Grok build-fast 모션 편은 새 가드에 걸려 `FRAMEFORGE_SFX_GUARD=off`로 렌더했다. 효과음 밀도가 가장 높은 것은 Opus 모션(13초에 12개)이다.
