# 품질 검사

README에서 옮긴 검사 도구 레퍼런스입니다. 결정성 린트(`npm run lint:video`)와 런타임 멱등성 검사(`--check-idempotent`)는 [rendering.md](rendering.md)의 "결정성 린트와 병렬 렌더" 절에 있습니다. 검사 순서는 `skills/frameforge-check/SKILL.md`, 구성 최소치는 [../samples/rules.md](../samples/rules.md)입니다.

## 글자 잘림 검사

글자 잘림 검사: 렌더는 프레임마다 글자의 실제 잉크 범위(캔버스 `measureText`)를 가장 가까운 `overflow`/`clip-path` 조상과 비교하고, 0.5px 넘게 잘리면 `Clipped text: "퍼즐" top 8.3px`처럼 그 프레임을 실패시킵니다. 스튜디오는 잘린 글자에 빨간 테두리를 그리고 아래 막대에 `글자 잘림 N곳`을 표시합니다. 글자와 마스크 사이에 이동(translate) 변환이 있으면 등장 애니메이션 중으로 보고 검사하지 않습니다. 확대·회전은 그대로 검사합니다. 티커처럼 일부러 잘리는 요소는 `data-clip="allow"`로 제외하고, 스튜디오는 웹폰트 로드가 끝난 뒤 한 번 더 검사합니다.

## 글자 겹침 진단의 범위

`text_overlap`은 DOM 텍스트의 `Range.getBoundingClientRect()` 경계 상자가 작은 상자의 20% 넘게 겹치는 후보를 보고합니다. 이 범위에는 글꼴 메트릭의 빈 공간이 포함될 수 있고, 같은 부모의 텍스트 범위는 하나로 합칩니다. 글자 잘림 검사와 달리 실제 잉크의 충돌·픽셀 가림을 측정하지 않습니다. 진단의 프레임·기간과 실제 저장 영상에서 보이는 글자를 함께 확인합니다.

읽을 글자가 실제로 충돌하면 시간이나 배치를 수정합니다. 경계 상자만 겹치고 글자 사이에 여유가 있다면 진단 코드와 상태는 유지하고, 확인한 프레임과 글자 사이의 간격을 기록합니다. 수치를 낮추거나 글자를 장식으로 표시해 경고를 숨기지 않습니다. 경계 상자 경고가 없다는 사실 역시 모든 프레임의 가독성을 증명하지 않습니다.

## 품질 검사 도구

- `frameforge brief-check <slug>`: 의도 장부의 `must` 행에서 명시된 초, 크기와 fps를 컴포지션과 대조한다. `10–15초`, `10-15 seconds`, `10 to 15 seconds`, `between 10 and 15 seconds`처럼 초 단위가 붙은 범위는 양끝을 포함한다. 예를 들어 12초는 10–15초 범위에 든다. 범위가 역순이거나 양수가 아니면 `duration_range_invalid`, 한 행에 분과 초, 별도 길이 또는 선택지가 섞여 구분하기 어려우면 `duration_ambiguous`를 보고한다. 분과 초를 합산하지 않으므로 실제 시간은 따로 확인한다. 한 값을 지정한 경우 기존의 0.5초 미만 차이 허용 기준은 그대로다. 이 검사는 자연어의 시간 표현이 영상 전체에 대한 것인지 자동으로 이해하지 못하며, 지원하지 않는 표현과 컴포지션 값을 읽을 수 없는 경우도 있다. 장면별 시간이나 대체된 요구는 문맥과 실제 결과를 따로 확인한다.
- `npm run frame-check -- <video.mp4>`: 인코딩된 영상에서 빈 화면 구간, 얼어붙은 구간(0.5초 전 프레임과 비교해 바뀐 픽셀 0.2% 미만이 1초 넘게 이어짐, 마지막 1초 끝 정지는 제외, `--hold`로 바꿈), 움직이는 프레임 비율(`motion share`), 중앙에 몰린 구성, 큰 요소가 없는 "얇은" 프레임 비율, 경계가 하나도 없는 프레임(한 가지 평평한 색이나 완전히 흐린 화면, `featureless`, 3프레임 연속이면 실패), 끝 정지(4초 이상 영상에서 마지막 2초의 motion share 0.5 미만이면 `end hold` 실패, `--hold`를 직접 주면 건너뜀)를 재고 통과·실패를 낸다(`scripts/frame-check.mjs`, 기준은 `docs/samples/rules.md`의 구성 최소치).
  검사에 사용할 프레임률은 1fps 이상의 유한한 수여야 한다. FFprobe가 원본을 1fps 미만으로 확인하면 `--fps`로 검사값을 높여도 지원되지 않는다. 기존 프레임 비교로 끝 2초의 움직임을 신뢰성 있게 판정할 수 없어 오류로 종료한다. 명시한 `--hold`는 0 이상의 정수이고 비교할 디코딩 프레임을 최소 `step + 1`개 남겨야 한다. `step`은 `max(1, round(fps / 30))`이므로 30fps는 두 개, 60fps는 세 개가 필요하다. 영상 자체가 이보다 짧으면 비교할 수 없어 오류로 종료한다. 기본 1초 hold가 비교에 필요한 프레임을 남기지 않는 짧은 영상은 hold를 0으로 두고 모든 프레임을 검사한다. 아직 비교 대상이 없는 시작 프레임은 정지·움직임 비율의 분모에서 제외한다. FFmpeg의 오류 수준 진단이나 실패 종료, 불완전 프레임 출력이 있으면 일부 영상만 검사해 통과시키지 않고 오류로 종료한다. 디코더가 오류를 보고하지 않는 모든 손상을 찾아낸다는 보장은 아니다.
- `node scripts/flash-check.mjs <video.mp4>`: WCAG 2.x·방송 플래시 지침 근사. 상대 휘도(sRGB 선형화)가 0.1 이상 바뀌고 어두운 쪽이 0.8 미만인 픽셀이 화면의 25 % 이상이면 전환 하나다. 반대 방향 전환 한 쌍이 플래시 하나이고, 1초 안에 플래시가 셋을 넘으면 실패다. 연속된 같은 방향 변화는 한 전환으로 센다. 회색 코드 값으로 재던 이전 방식은 어두운 화면의 작은 변화까지 플래시로 셌다.
- `python3 scripts/assets/score-report.py <music.wav>`: 통합 음량, LRA, 트루 피크, 크레스트 팩터, 4대역 스펙트럼 균형, 스테레오 상관.
