# 제품 설명 영상 만드는 법

실제 제품 화면을 캡처해 버튼을 하나씩 가리키는 설명 영상을 만드는 방법이다. 색, 글꼴, 모션 일반 규칙은 `docs/guides/motion-graphics.md`에, 오디오와 아이콘과 캡처 기본 절차는 `docs/guides/assets.md`에 있다. 이 문서는 그 두 문서가 다루지 않는 것만 적는다.

캡처는 사용자가 준비한다. 저장소에는 실제 사이트 캡처도, 캡처 스크립트도 없다. 2절이 설명하는 Playwright나 CDP 스크립트로 직접 찍는다. 이 방법을 처음 정리한 기준 작품 youtube-intro는 실제 사이트 화면을 써서 배포하지 않는다. 아래에서 "원래 작품"은 그 작품을 뜻한다. 저장소에서 바로 열어 볼 수 있는 코드는 `examples/samples/_template/Spot.tsx`의 `Screen`과 `Callout`이다.

## 1. 언제 이 형식을 쓰는가

이 형식은 사람이 실제 화면에서 무엇을 누를지 알아야 할 때 쓴다. 제품 둘러보기, 새 기능 소개, 온보딩 도움말이 여기에 든다. 화면 한 장에 콜아웃 몇 개를 얹고 카메라를 밀어 넣는 구성이라서, 추상적인 개념이나 숫자 이야기에는 맞지 않는다. 그런 주제는 `docs/guides/motion-graphics.md`의 일반 스팟 구성을 쓴다.

**샘플 규칙보다 앞서는 규칙 하나.** 실제 화면을 보여 주고, 아무것도 지어내지 않는다. `docs/samples/rules.md`는 실제 회사, 제품, 로고, 수치, 얼굴을 금지한다. 제품 설명 영상은 이 금지를 일부러 깬다. 대신 더 좁은 규칙을 지킨다.

- UI를 다시 그리지 않는다. 화면은 캡처한 PNG 그대로 쓴다.
- 화면에 없는 숫자를 만들지 않는다. 캡처에 보이는 조회수나 좋아요 수는 그대로 두되, 라벨에 새 숫자를 쓰지 않는다.
- 버튼은 눈에 보이는 동작으로만 설명한다. 라벨은 "공유. 친구에게 보내기", "저장. 나중에 다시 보기"처럼 버튼이 하는 일 한 가지만 말한다. 추천 알고리즘이나 수익 같은 화면 밖의 주장은 하지 않는다.

이 규칙은 얼굴 금지도 덮는다. 영상 서비스의 재생 페이지를 찍으면 플레이어에 영상 속 인물의 얼굴이 크게 찍힐 수 있다. 제품이 허용한다면 인물이 아닌 장면에서 멈춘 페이지를 고르는 편이 낫다. 3절에서 다시 다룬다.

## 2. 화면 확보

기본 절차 다섯 단계는 `docs/guides/assets.md` 4절에 있다. 여기서는 캡처 스크립트가 해야 할 세부를 적는다.

**영상 크기 그대로 찍는다.** 임시 프로필로 headless Chrome을 띄우고 `--window-size=1920,1080`, `--force-device-scale-factor=1`, `--hide-scrollbars`를 준다. 이어서 CDP `Emulation.setDeviceMetricsOverride`로 1920×1080, 배율 1을 다시 건다. 캡처 픽셀이 컴포지션 픽셀과 같으면 DOM에서 잰 좌표를 변환 없이 콜아웃에 쓸 수 있다. 세로 영상이면 1080×1920으로 찍으면 같은 원리가 성립한다(추론, 세로 캡처는 해 보지 않았다).

**언어는 두 곳에서 맞춘다.** 실행 인자 `--lang=ko-KR`은 브라우저 UI 언어를 정하고, `Network.setExtraHTTPHeaders`로 보내는 `Accept-Language: ko-KR,ko;q=0.9`는 사이트가 고르는 언어를 정한다. 둘 다 쓴다. 그래도 지역은 따로 논다. 원래 작품의 홈 캡처에는 로고 옆에 "JP" 표시가 찍혔다. 원인은 접속한 IP의 지역으로 보인다(추론). 지역 표시가 영상에 맞지 않으면 그 부분을 잘라 내거나 콜아웃 밖으로 둔다.

**기다리고, 대화상자를 지운다.** 페이지마다 고정 시간을 기다린다. 원래 작품은 목록 페이지에 6초, 재생 페이지에 8초를 썼다. 그 뒤 동의 팝업과 대화상자 요소를 DOM에서 지운다. 셀렉터는 제품마다 다르다. 한 번 찍어 보고 화면에 남은 팝업의 요소를 찾아 목록에 더한다.

**스크롤과 영상을 고정한다.** 캡처 전에 `window.scrollTo(0,0)`으로 맨 위로 올리고 1.5초 기다린다. 영상이 있는 페이지에서는 `document.querySelector('video')?.pause()`로 영상을 멈춘다. 멈추지 않으면 찍을 때마다 다른 프레임이 들어간다. 아래쪽 영역이 필요하면 `scrollIntoView({block: 'start'})` 뒤 2.5초 기다리고 찍는다.

**요소 위치를 DOM에서 잰다.** 같은 페이지에서 `getBoundingClientRect()`로 x, y, 폭, 높이를 재어 `.scratch/<product>/rects.json`에 쓴다. 셀렉터는 콤마로 후보를 여러 개 준다.

```js
const rects = async (selectors) => evalJs(`JSON.stringify(Object.fromEntries(${JSON.stringify(selectors)}.map(([k, s]) => { const el = document.querySelector(s); if (!el) return [k, null]; const r = el.getBoundingClientRect(); return [k, {x: Math.round(r.x), y: Math.round(r.y), w: Math.round(r.width), h: Math.round(r.height)}]; })))`);
```

`null`은 셀렉터가 아무것도 찾지 못했다는 뜻이고, 0은 찾은 요소가 화면에 그려지지 않았다는 뜻이다. 원래 작품에서는 좋아요, 공유, 채널 이름 같은 값이 0이었다. 로그아웃 상태의 빈 피드처럼 요소 자체가 없으면 `null`이 나온다.

**DOM이 틀리면 PNG에서 잰다.** DOM 사각형은 눈에 보이는 상자와 다를 수 있다. 원래 작품의 검색창은 DOM에서 x 566, 폭 732였지만 그려진 상자는 x 642, 폭 600이었다. DOM 값은 감싸는 컨테이너였다. 0이 나온 요소는 처음부터 PNG를 잘라 픽셀 경계를 읽는다. 어느 쪽이든 최종 값은 그려진 상자 기준이다. 고친 값과 이유는 `prompt.md`에 적는다.

**파일 위치와 이름.** 스크립트와 측정값은 `.scratch/<product>/`에 둔다. 작품이 쓰는 캡처는 `public/` 아래 원하는 폴더에 두고 그 폴더를 `.gitignore`에 추가한다. 이름은 페이지 역할로 짓는다(`home.png`, `channel.png`, `watch.png`). 스크립트가 쓴 파일을 `public/`으로 복사할 때 이미지를 고치지 않는다.

**`prompt.md`에 남길 것.** 원본 PNG 목록, 캡처 날짜, 로그아웃 상태로 찍은 수정하지 않은 캡처라는 사실, 쓰지 않은 캡처를 적는다. 예를 들면 "Unmodified logged-out captures of <site> (Korean UI), 1920x1080, captured <date>. `comments.png` is not used."다. 제품 화면은 바뀌므로 날짜가 없으면 나중에 영상과 실제 화면이 다른 이유를 설명할 수 없다.

## 3. 개인정보와 권리

`docs/guides/assets.md` 4절의 개인정보와 상표 항목을 먼저 읽는다. 여기서는 이유와 범위를 더 적는다.

**로그아웃 상태로 찍는 이유.** 로그인하면 화면이 찍는 사람의 것이 된다. 개인 피드, 시청 기록, 구독 목록, 아바타, 계정 이름이 들어간다. 로그아웃 캡처에는 이것이 없다. 오른쪽 위에는 아바타 대신 로그인 버튼이 있고, 피드 자리에는 빈 안내 카드가 있는 경우가 많다. 임시 프로필(`mkdtempSync`)을 쓰면 평소 브라우저의 쿠키도 섞이지 않는다.

**그래도 남는 것.** 로그아웃해도 다른 사람의 공개 콘텐츠는 찍힌다. 재생 페이지라면 영상 속 인물의 얼굴, 채널 이름, 추천 썸네일과 그 채널 이름, 조회수, 영상 설명이 들어간다. 이것들은 공개된 것이지만 설명 영상의 주제는 아니다. 줄이는 방법은 세 가지다.

- 제품 운영사의 공식 채널이나 공식 페이지를 고른다.
- 댓글 목록은 쓰지 않는다. 댓글을 설명해야 하면 목록이 아니라 헤더(`댓글 1,125개` 같은 줄)만 가리킨다.
- 개별 댓글 작성자를 확대하거나 가리키지 않는다. 다른 사람의 이름이나 아바타가 크게 보이면 카메라를 다른 곳으로 옮기거나 그 부분을 화면 밖으로 둔다.

**상표.** 캡처 속 로고와 제품 이름은 그 회사의 상표다. 설명 영상에서 제품을 알아보게 하는 용도로만 보여 주고, 소유자를 `prompt.md`에 적는다. 문장은 "<제품> and its logo are trademarks of <소유자>, shown for identification in an explainer" 형태로 쓴다. 캡처에 찍힌 로고를 그대로 보여 주는 것과 로고를 다시 그리거나 흉내 낸 마크를 영상의 브랜딩으로 쓰는 것은 다르다. 후자는 하지 않는다. 오프닝과 엔딩은 로고 없이 글자와 아이콘으로 만든다.

**제품 소유자에게 물어야 할 때.** 아래는 판단 기준이며 법률 자문이 아니다. 영상이 광고나 판매에 쓰일 때, 로그인해야 보이는 화면이나 출시 전 화면을 보여 줄 때, 캡처 밖에서 로고를 따로 쓰고 싶을 때, 고객 데이터가 화면에 들어갈 때, 영상이 그 회사의 공식 자료처럼 보일 수 있을 때는 소유자의 허락을 받는다. 자기 회사 제품이면 담당 팀의 확인을 받는다.

## 4. 콜아웃 설계

콜아웃은 네 부분이다. 어둡게 덮는 막, 막에 뚫린 구멍, 구멍 둘레의 강조선, 라벨 카드다. 코드는 `examples/samples/_template/Spot.tsx`의 `Callout`이다. 아래 숫자는 그 파일에서 읽었다.

**구멍 뚫린 막.** 막은 SVG 경로 하나다. 화면 전체 사각형과 대상 사각형을 한 경로에 넣고 `fillRule="evenodd"`로 채우면 대상 자리만 비어 있다. 색은 ink, 불투명도 0.55다. 막은 콜아웃 구간 시작과 끝에서 8프레임씩 나타나고 사라진다(`span(frame, at, 8) * (1 - span(frame, end - 8, 8))`).

**강조선.** accent 색 사각형을 대상보다 8px 크게 그린다(`pad = 8`). 선 굵기 6, 모서리 반경 10이다. `_template`은 화면 전체를 1.04로 한 번 미는 것이 전부라 배율 보정을 하지 않는다. 대상 중심으로 크게 미는 카메라(5절) 안에 막과 강조선을 넣으면 카메라가 밀 때 선도 굵어진다. 그때는 선 굵기를 `6 / k`, 반경을 `10 / k`로 나눠 화면에서 늘 6px로 보이게 한다. `k`는 카메라 배율이다. 원래 작품이 이 방식을 썼다.

**라벨 카드.** 카드는 ink 배경에 paper 글자, `SIZES.label`(38px) Noto Sans KR 500, 왼쪽에 아이콘 하나다. 높이는 `SIZES.label * 2.4`다. 배치 규칙은 세 가지다.

- 대상을 덮지 않는다. 아래에 놓을 자리가 있으면(`y + h + pad + 40 + cardH < H - SIZES.marginY`) 대상 40px 아래에, 없으면 40px 위에 놓는다.
- 세이프 영역 안에 둔다. 세로 여백은 위 식이 지킨다. 가로는 카드를 화면 가운데에 놓는 것으로 지키며, 코드가 가로 96px 여백을 따로 검사하지는 않는다. 라벨 문장이 길면 직접 잰다.
- 화면 속 제품 글자가 작으면 라벨을 최소치보다 키운다. 원래 작품은 56px를 썼다. 5절의 카메라를 쓰면 라벨은 카메라 컨테이너 밖에 둔다. 그래야 카메라가 밀어도 글자 크기가 그대로다.

**한 번에 하나.** 활성 콜아웃은 `callouts.findIndex(c => frame >= c.at && frame < c.end)`처럼 하나만 고른다. 라벨 두 개가 동시에 뜨지 않는다.

**75프레임 간격.** 콜아웃은 대략 75프레임(2.5초)마다 바꾼다. `_template`의 라벨은 16프레임 스프링으로 들어오고 구간 끝 6프레임 전에 빠진다. 75프레임이면 들어오고 읽고 빠지는 데 충분하다.

**아이콘 하나씩.** 콜아웃마다 아이콘 하나를 붙인다. 검색에 돋보기, 구독에 종, 공유에 화살표처럼 버튼과 같은 뜻의 아이콘을 고른다. 같은 아이콘이 오프닝과 마무리에 다시 나오면 영상 전체가 묶인다. 실제 화면 콜아웃에서는 `lucide-react` 표식을 쓸 수 있다. 라이브러리와 라이선스는 `docs/guides/assets.md` 2절을 따른다.

**이웃 대상 사이는 스프링으로 옮긴다.** 같은 화면 안에서 다음 대상으로 넘어갈 때 구멍과 강조선을 끊고 새로 그리지 않는다. 그 화면의 콜아웃 사각형을 차례로 `lerp`하고, 각 단계의 진행값을 `pop(frame, c.at, 18, true)`로 준다. 그러면 구멍이 18프레임 동안 옆 버튼으로 미끄러진다. 눈이 구멍을 따라가므로 새 대상을 찾는 시간이 없다. 원래 작품이 이렇게 했다. `_template`의 `Callout`은 콜아웃마다 따로 나타나므로 이 동작을 하려면 고쳐 써야 한다.

## 5. 카메라

아래 계산은 원래 작품의 `camera()`에서 정리한 방법이다. 저장소의 샘플 중 이 계산을 쓰는 파일은 없다.

**대상 중심을 화면 중심으로 옮긴 뒤 키운다.** 스크린샷은 원래 크기 1920×1080 그대로 `<Img>`에 넣고, 감싼 div를 변환한다. `transformOrigin: '0 0'`일 때 대상 중심 `(fx, fy)`를 화면 중심에 두는 변환은 아래와 같다.

```ts
const k = s * B; // B는 카메라 1.0일 때 카드 배율. 원래 작품은 0.82
const tx = W / 2 - k * fx;
const ty = H / 2 - k * fy;
// transform: translate(tx, ty) scale(k)
```

`s`는 카메라 배율이다. 카메라 1.0에서 스크린샷은 카드 크기로 가운데 놓이고, 뒤에 어긋난 ink 그림자 블록이 보인다. `_template`의 `Screen`이 이 카드다. 그 바깥은 무대 색이다.

**밀었을 때는 스크린샷이 늘 화면을 덮는다.** 밀어 넣은 화면 가장자리에 무대가 보이면 실수처럼 보인다. 조건은 두 가지다. 첫째, 밀 때 `k >= 1`이어야 한다. 둘째, 중심을 그대로 쓰면 가장자리 근처 대상에서 스크린샷 끝이 화면 안으로 들어온다. 그래서 매 프레임 중심을 `[H / 2 / k, H - H / 2 / k]` 안으로 자른다(가로도 같다). 스프링 중간 프레임에도 이 자르기를 건다. 그 대가로 가장자리 대상은 화면 가운데에 오지 않는다.

**배율의 실제 상한.** 버튼은 1.5–1.7, 플레이어처럼 큰 대상은 `1 / B`다. `1 / B`는 `k`를 정확히 1로 만들어 스크린샷이 화면을 꼭 채운다. `B = 0.82`일 때 카메라 1.15는 `k = 0.943`이라 가장자리에 틈이 생긴다. 1.7보다 키우지 않는 이유는 두 가지다(추론). 캡처는 배율 1의 래스터라서 `k = 1.39`를 넘기면 글자가 흐려진다. 또 배율이 클수록 위의 중심 자르기가 대상을 가운데에서 더 멀리 민다.

**이징과 유지 시간.** 카메라 키는 `spring({durationInFrames: 18, config: {overshootClamping: true}})`로 섞는다. 넘침이 없으므로 화면이 출렁이지 않는다. 키를 목록에 차례로 쌓고, 각 키가 이전 상태에서 자기 값으로 보간하게 한다. 푸시가 끝난 뒤 다음 키까지 최소 30프레임 이상 멈춰 둔다. 버튼이 한 줄로 모인 곳은 한 번 밀고 그대로 둔 채 구멍만 옮긴다.

**화면을 바꾸기 전에 1.0으로 돌아온다.** 카드 전체가 보여야 시청자가 화면이 바뀐다는 것을 안다. 복귀를 화면 슬라이드보다 15프레임 먼저 시작하는 편이 안전하다(추론). 복귀와 슬라이드를 같은 프레임에 시작해야 한다면 슬라이드 거리에 `Math.max(1, k)`를 곱한다. 그러면 밀린 상태에서도 나가는 화면이 화면 밖까지 빠진다. 원래 작품이 이렇게 했다.

## 6. 30초 둘러보기의 장면 구조

900프레임을 아래처럼 나눈다. 원래 작품의 구조를 정리한 틀이다.

1. **헤드라인과 아이콘 줄(0–75).** ink 배경에 "<제품>, 버튼 여섯 개만 / 알면 됩니다" 같은 문장이 글자 단위로 올라오고, 아래에 아이콘이 스프링으로 튀어나온다. 영상이 무엇을 몇 개 알려 줄지 첫 2.5초에 약속한다.
2. **화면 둘 또는 셋(75–375).** 첫 화면 카드가 아래에서 올라온다(`_template`의 `Screen`). 화면마다 콜아웃을 한두 개 건다. 다음 화면은 옆으로 밀려 들어오고 이전 화면은 반대로 나간다. 페이드는 쓰지 않는다.
3. **버튼 줄(375–600).** 버튼이 한 줄로 모인 곳에 카메라를 한 번 밀고 그대로 둔다. 구멍만 75프레임마다 옆 버튼으로 옮긴다.
4. **댓글이나 아래쪽 영역(600–675).** 카메라를 1.0으로 돌리고 화면 아래쪽 헤더 하나를 가리킨다. 헤더가 화면 끝에 붙어 있으면 컨테이너를 올려 넉넉히 들어오게 한다.
5. **마무리(675–899).** 화면 카드가 아래로 빠지고, 오프닝의 아이콘이 이번에는 단어와 함께 다시 나온다. 위에는 "이제 눌러 보세요" 같은 한 줄이 있다. 840 전에 모두 멈추고 마지막 2초는 움직이지 않는다.

소리는 콜아웃 시작마다 `click.wav`, 화면이 미끄러질 때마다 `whoosh.wav`다. 구멍과 화면 슬라이드에 `<MotionProbe>`를 달고 `<MotionSound>`로 소리를 매핑하는 쪽이 기본이다. `_template`의 `Screen`은 이미 `family="card"` 프로브를 단다. 렌더러는 0.5초보다 가깝거나 4초 안에 3개를 넘는 효과음을 거부하므로, 75프레임 간격의 콜아웃은 이 기준을 넘지 않는다(추론). 음원은 작품마다 `audio.json`에서 생성하며 방법은 `docs/guides/assets.md` 1절에 있다.

## 7. 검사

일반 자기 검사 루프는 `docs/guides/motion-graphics.md` 8절에 있다. 제품 설명 영상은 그 위에 콜아웃 정확도 검사 여섯 가지를 더한다.

1. **강조선이 대상과 6px 안에서 맞는다.** 키프레임 PNG에서 강조선 안쪽 경계와 그려진 버튼 경계의 차이를 잰다. 6px을 넘으면 사각형 값이나 카메라 계산을 고친다. 기준은 DOM 값이 아니라 그려진 상자다(2절).
2. **라벨이 세이프 영역 안에 있다.** 카드 전체가 좌우 96px, 상하 54px 안에 있는지 본다. 가로는 코드가 검사하지 않으므로 긴 라벨은 눈으로 확인한다.
3. **밀었을 때 화면 가장자리에 틈이 없다.** 푸시 구간의 키프레임 네 모서리에 무대 색이나 그림자 블록이 보이면 실패다. 스프링 중간 프레임도 하나 이상 본다.
4. **글자 잘림 가드를 통과한다.** `src/studio/textGuard.ts`의 `findClippedText`는 텍스트 노드마다 자르는 조상(오버플로나 `clipPath`가 있는 요소, 또는 루트)을 찾고, 그 사이 `transform`을 잠시 지운 상태에서 글자 잉크가 조상 밖으로 나가는지 잰다. 렌더러는 걸리면 `Clipped text` 오류로 멈춘다(`src/studio/runtime.tsx` 89행). 스크린샷 속 글자는 픽셀이라 가드가 보지 못한다. 카메라가 캡처 글자를 잘라도 오류는 나지 않는다. 라벨을 카메라 컨테이너 안에 넣으면 가드는 밀기 전 위치에서 재므로, 푸시가 라벨을 잘라도 놓칠 수 있다(추론). 라벨을 컨테이너 밖에 두는 이유다. 라벨에 `data-clip="allow"`를 붙여 가드를 피하지 않는다.
5. **콜아웃이 머무는 동안 멈춰 있다.** 라벨이 다 들어온 뒤 구간 끝까지 카메라와 구멍이 움직이지 않아야 읽힌다. 같은 이유로 버튼 줄 구간은 화면 대부분이 멈춘다. `docs/samples/rules.md`의 `frame-check`는 바뀐 픽셀 0.2% 미만이 120프레임 넘게 이어지면 실패로 본다. 75프레임마다 움직이는 구멍과 라벨이 이 기준을 넘기는지 직접 확인한다.
6. **효과음이 콜아웃 시작 프레임에 있다.** 손으로 놓았다면 `click.wav`의 `<Sequence from={n}>` 목록이 `callouts`의 `at` 값과 같은지 비교한다. `MotionSound`를 쓰면 렌더 로그 `motionSounds`의 프레임이 `at` 값과 같은지 비교한다.

**컨택트 시트.** 렌더러는 넘겨받은 entry로 자기 vite 서버를 `127.0.0.1:4318`에 직접 띄운다(`strictPort`, `scripts/render.mjs` 367–369행). 그래서 따로 서버를 켤 필요는 없지만, 4318을 다른 프로세스가 쓰고 있으면 실패한다. `FRAMEFORGE_PORT`로 포트를 바꿀 수 있다. 스튜디오 개발 서버(`npm run dev`)는 4317이다. 렌더 전에 entry 폴더의 `audio.json`으로 음원도 생성한다. `--frames`를 주면 그 프레임만 그려 칸 폭 480px, 최대 4열로 타일한다. 가드도 이때 돈다. 검사 프레임은 `prompt.md`에 적은 것을 쓴다.

```sh
npm run render -- examples/samples/<slug>/entry.tsx <CompositionId> renders/samples/<slug>-sheet.png --frames 40,110,200,270,340,400,480,560,640,760,880
```

**스트립과 숫자 검사.** MP4를 만든 뒤 15프레임마다 한 장을 붙인 스트립과 `frame-check`를 돌린다. 명령은 `docs/guides/motion-graphics.md` 8절과 `docs/samples/rules.md`에서 가져왔다. 단 `tile`의 칸 수는 `durationInFrames / 15`와 같아야 한다. 8절의 `tile=8x5`는 600프레임용 40칸이라 900프레임 작품에 쓰면 600프레임 뒤가 빠진다. 아래는 900프레임용 60칸이다.

```sh
ffmpeg -i renders/samples/<slug>.mp4 -vf "select='not(mod(n\,15))',scale=320:-1,tile=10x6" -frames:v 1 renders/samples/<slug>-strip.png
npm run frame-check -- renders/samples/<slug>.mp4
```

## 8. 체크리스트

각 항목에 예 또는 아니오로 답한다. 일반 항목은 `docs/guides/motion-graphics.md` 9절의 체크리스트를 같이 쓴다.

**화면 확보**
- [ ] 로그아웃 상태, 임시 프로필로 찍었다.
- [ ] 캡처가 컴포지션과 같은 크기이고 배율이 1이다.
- [ ] `--lang`과 `Accept-Language`를 둘 다 맞췄고, 지역 표시를 확인했다.
- [ ] 팝업과 대화상자를 지웠고, 영상은 멈춰 있다.
- [ ] 콜아웃 대상마다 사각형이 있고, 0이나 `null`인 값은 PNG에서 다시 쟀다.
- [ ] 캡처가 `public/` 아래 폴더에 수정 없이 있고, 그 폴더가 `.gitignore`에 있다.
- [ ] `prompt.md`에 원본 목록, 캡처 날짜, 로그아웃 원본이라는 사실, 쓰지 않은 캡처가 있다.

- [ ] 다시 그린 UI가 없다.
- [ ] 화면에 없는 숫자가 없다.

**콜아웃과 카메라**
- [ ] 콜아웃은 한 번에 하나이고, 약 75프레임마다 바뀐다.
- [ ] 콜아웃마다 아이콘이 하나 있다.
- [ ] 라벨이 대상을 덮지 않고 세이프 영역 안에 있으며, 화면 속 글자보다 확실히 크다.

- [ ] 밀었을 때 `k >= 1`이고 가장자리에 틈이 없다.
- [ ] 버튼 배율은 1.7 이하, 큰 대상은 `1 / B`다.
- [ ] 화면을 바꾸기 전에 카메라가 1.0으로 돌아온다.
