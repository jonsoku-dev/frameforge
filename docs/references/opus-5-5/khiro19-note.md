# khiro19, Opus 5.5 모션 그래픽 검증 (note.com)

주소: https://note.com/khiro19/n/n202b016a0c92

2026-10-20에 사용자가 붙여 넣은 본문으로 읽었다. 원문 페이지를 직접 열지는 않았다. 유튜브 영상의 글 요약이며, Opus 5.5와 GPT-6 Astra에게 같은 과제를 주고 비교한 기록이다. 영상 자체와 블라인드 테스트 서비스는 보지 않았다.

## 세 가지 과제와 판정

| 과제 | 프롬프트 요지 | 판정 근거 |
| --- | --- | --- |
| 15초 쇼릴 | 레퍼런스 없이 "할 수 있는 건 다 쏟아부어" | 챕터 전환이 끊기지 않음. 점이 작아졌다 커져 글자가 되고, 오브젝트가 뭉쳤다 터지며 다음 챕터가 됨. Astra는 깜빡인 뒤 다음 챕터 |
| SaaS 데모 30–40초 | 서비스 링크 + 레퍼런스 영상, 먼저 분석과 기획을 보고 | 문제 공감 → 앱 화면으로 증명하는 서사. 핵심 기능에 줌인/줌아웃 |
| 교육 영상(랩) | 가사 → 음악(ElevenLabs) → 레퍼런스 창고에서 고르게 → 제작 | 키네틱 타이포가 뜻을 담음(Consistency를 돌리고 합침). 전환이 다음 장면으로 이어짐 |

## Frameforge에 적용하는 규칙

1. 장면은 직전 장면의 물체에서 태어난다. 컷으로 바꾸지 않는다. 원이 커져 배경이 되고, 선이 다음 장면의 밑줄이 된다. 이미 `docs/references/opus-5-5/aiidelist.md`의 규칙과 같다. 이 글은 그 규칙이 비교 평가에서 결정적이었다고 말한다.
2. 핵심 순간에 카메라가 민다. 충돌, 핵심 기능, 이름 등장에서 1.0→1.05 정도의 푸시와 복귀. 전체 장면에 상시로 쓰지 않는다.
3. 레퍼런스를 먼저 분석하고, 무엇을 왜 가져오는지 보고한 뒤 타임라인 시트를 만든다. 이 저장소의 `docs/films/<film>/prompt.md`와 `shots.md`가 그 시트다. 기획서에 "참고 레퍼런스와 이유" 항목을 둔다.
4. 제작 전에 정지 화면 여러 장을 한 장으로 모아 보고 고친다. `npm run render -- <entry> <id> <sheet.png> --frames 30,120,...` 로 만든다.
5. 음악은 잔잔하게 시작해 몰입이 높아지는 기승전결. 이 엔진은 작품마다 `audio.json` 사양에서 음악을 합성한다(`npm run score`, `docs/audio-score.md`). 효과음은 모션에서 파생된다.

## 이 글에서 가져오지 않은 것

모델 승률 통계와 블라인드 테스트 서비스 홍보. ElevenLabs 커넥터 설치 안내. 플로우덱 앱의 상세.
